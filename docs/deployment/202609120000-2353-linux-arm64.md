# Linux arm64 候选部署

本候选是 rss-mdm 单一生产可执行文件的 OCI 镜像，平台 linux/arm64，运行用户 10001:10001。版本、源码 SHA、Cargo.lock、依赖来源、嵌入迁移、二进制、OCI manifest 与归档 SHA-256 由 candidate.json 记录。smoke.json 记录实际候选验收结果；没有该记录不能声称候选运行验证通过。T3 和生产发布另行验收。

## 构建与验证

从干净已提交源码运行，构建机需要 Docker Buildx 和私有 Git 只读凭据。授权头文件必须普通文件且仅 owner 可读；它只作为 BuildKit secret 提供给 cargo fetch，编译在离线网络中进行，凭据不进入编译层或运行镜像。

~~~sh
python3 hack/release.py --output artifacts/candidate --git-auth-header-file /private/azure-header
MDM_IDENTITY_CANDIDATE=/absolute/approved-identity-candidate python3 hack/candidate_smoke.py --candidate artifacts/candidate
~~~

首次构建按 deployment/providers.lock.json 获取固定 Rust 与 Debian 镜像。MDM 专属缓存只复用依赖和 Cargo 编译结果。交付携带 server.oci.tar、candidate.json、smoke.json、smoke.log、evidence 与示例配置；使用归档前核对 manifest 和 SHA-256。

构建仅在全部校验通过后发布候选目录；失败会清理暂存内容，可用原命令重试。已存在的候选目录不会被覆盖。

候选 smoke 启动实际 arm64 OCI，用真实 TLS PostgreSQL 与批准的 Identity 候选执行 migrate、迁移重放、serve、livez、readyz、在线登录、资产与 run 查询、权限拒绝和正常停机。资产是明确的测试持久数据；测试 TCP 转发只保留原 TLS 连接，不构成生产拓扑或真机采集证明。

## 运行前提与升级

需要与现有 I01/F04 相同的 PostgreSQL、Identity、Windows CA/协议保护密钥与 TLS 文件。database=mdm_api、access_database=mdm_access、runtime_database=mdm_runtime 必须连接同一数据库；runtime_database 是 Observation 与 Projection 两个独立专属池的共同配置，每池最多 4 个连接。读取池与接入池各自最多 4 个连接。配置必填，不提供旧字段回退。

由安装 owner 使用 mdm_owner 执行迁移。停止旧进程并备份数据库及关联密钥后，使用候选执行：

~~~sh
docker load --input server.oci.tar
docker run --rm --network host --mount type=bind,src=/private/mdm,dst=/run/mdm,readonly IMAGE migrate --config /run/mdm/migrate.json
docker run --name rss-mdm --network host --mount type=bind,src=/private/mdm,dst=/run/mdm,readonly IMAGE serve --config /run/mdm/config.json
~~~

IMAGE 替换为 candidate.json 中的固定镜像身份。配置与秘密文件由运行 UID 10001 持有，秘密权限 0600。镜像不嵌入配置、私钥或数据库口令。Linux host 网络让浏览器回环监听与同机受控 HTTPS 反向代理配合；Windows 协议监听按配置直接终止 TLS/mTLS。

追加 windows-collection-v1，旧迁移摘要不变。升级清空旧短期管理会话与响应缓存，不伪造历史 run；身份、证书、操作、审计及既有 Inventory 保留。不支持旧二进制与新 schema 混跑。回退需要停止进程并恢复整套一致数据库/密钥备份，不能删除迁移账本强行降级。

## 就绪、停机与恢复

/livez 表示进程可响应。/readyz 只有启动 admission 成功、首次有界恢复及投影通过、工作任务仍运行且尚未停机时才返回 200。已有 backlog 可以在后续有界调用中继续处理；资产/run 查询显示 receipt 和投影状态，ready 不表示所有历史数据已经追平。健康查询不另行探测外部服务。

SIGINT/SIGTERM 先停止接入并排空请求，再取消和 join Inventory 工作任务，最后关闭专属存储。整个关闭预算 40 秒；任一关键任务异常退出、存储不可继续或关闭失败返回非零退出码。部署 owner 决定进程重启策略，应用不自建监督循环；重启读取原 CollectionRun 和 RSS checkpoint。

监控 mdm_inventory_progress、mdm_management_retention_failure、mdm_shutdown_failure 和 audit_failure。日志仅记录闭合类别与操作坐标，不打印字段值、协议正文、provider 错误原文或密钥。不要通过换 batch ID、修改 sealed run 或清理 receipt/checkpoint 来处理提交未知。
