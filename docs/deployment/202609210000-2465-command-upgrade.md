# 命令服务安装与版本切换（#2465 / #2463）

运行期只接受新 schema 与必填 `command_database`；不保留旧配置默认值、双写或旧事务入口。版本切换必须先停旧服务，并核对目标版本的安装约束，再更新配置并启动新服务。不存在新旧应用同时写入的支持声明。

新安装在原有角色 bootstrap 后执行 `crates/app/schema/commands-roles.sql`。当前统一资产版本要求全新安装；已有部署不得仅追加角色后尝试原地升级，也不得通过自动清库绕过拒绝。由数据库管理员为 `mdm_command_runtime` 单独启用 LOGIN、设置登录秘密；迁移器继续使用非超级用户 `mdm_owner`，运行角色不执行 DDL。

运行 `rss-mdm migrate --config <migration.json>`：先核对迁移账本。全新安装包含 device-command、reconcile、commands 以及 inventory-v2、assets-management 单元；完整当前账本允许重放，并核对实例、存储 lineage/epoch、租户和角色。由于 #2463 替换资产契约，旧版本的完整前缀也明确拒绝，不再沿用命令功能单独交付时的前向追加能力。缺失、未知、摘要变化或未完成记录均拒绝；失败不会通过删除账本或清空业务表自动修复。

迁移单元和 ledger intent 分别保留中断证据。SQL 执行或完成确认不确定时，由运维检查数据库实际状态和对应不可变 SQL，恢复到可确认的安装状态后再执行；禁止将 `complete=false` 当作可以盲目重跑 DDL 的授权。迁移成功不代表旧二进制可以回滚运行；回退须使用停写后的匹配数据库备份和配置。

`command_database` 指向与其他产品角色相同的数据库，但使用独立凭据文件。更新所有部署输入生成器和 secret 挂载。启动时检查组件与产品 catalog、FORCE RLS 和运行权限；过宽权限或结构漂移拒绝启动。需要人工修复的存储错误不会降级为测试身份或旧实现。
