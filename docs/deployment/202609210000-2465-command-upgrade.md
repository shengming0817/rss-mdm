# 命令服务前向升级（#2465）

运行期只接受新 schema 与必填 `command_database`；不保留旧配置默认值、双写或旧事务入口。升级必须先停旧服务，再迁移、更新配置并启动新服务。不存在新旧应用同时写入的支持声明。

新安装在原有角色 bootstrap 后执行 `crates/app/schema/commands-roles.sql`。现有安装只执行这个新增角色脚本，不重跑已有 CREATE ROLE 脚本。由数据库管理员为 `mdm_command_runtime` 单独启用 LOGIN、设置登录秘密；迁移器继续使用非超级用户 `mdm_owner`，运行角色不执行 DDL。

运行 `rss-mdm migrate --config <migration.json>`：先核对安装的实例、存储 lineage/epoch、租户和角色，以及已完成迁移单元的精确摘要。当前新增 device-command、reconcile 组件 schema 与产品 commands 单元，旧单元不改写。已知完整前缀可前向追加，缺中间单元、未知单元、改过摘要或未完成记录拒绝；失败不会通过删除账本或清空业务表自动修复。

迁移单元和 ledger intent 分别保留中断证据。SQL 执行或完成确认不确定时，由运维检查数据库实际状态和对应不可变 SQL，恢复到可确认的安装状态后再执行；禁止将 `complete=false` 当作可以盲目重跑 DDL 的授权。迁移成功不代表旧二进制可以回滚运行；回退须使用停写后的匹配数据库备份和配置。

`command_database` 指向与其他产品角色相同的数据库，但使用独立凭据文件。更新所有部署输入生成器和 secret 挂载。启动时检查组件与产品 catalog、FORCE RLS 和运行权限；过宽权限或结构漂移拒绝启动。需要人工修复的存储错误不会降级为测试身份或旧实现。
