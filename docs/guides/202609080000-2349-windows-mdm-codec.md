# Windows MDM V1 编解码与关联

`rss-mdm-windows-mdm` 是产品仓的纯内存协议包。它解析与编码协议，不访问网络、文件、数据库或系统时钟；认证注册、证书验证/签发、HTTP/mTLS、会话重放存储、采集汇总及 Inventory 由调用方拥有。

## 已实现的协议配置

- XML 1.0、UTF-8（可带 BOM）、SOAP 1.2、WS-Addressing 2005/08、SyncML 1.2 / DM/1.2。
- Windows desktop `CIMClient_Windows`、服务端 EnrollmentVersion 4.0、Discovery 接受规范 RequestVersion 1.0–7.0、OnPremise。SOAP GetPolicies/Issue 请求需要结构化 UsernameToken（非空 u:Id，无固定取值）；解析不会验证口令。时间戳仅检查 RFC3339 格式，认证方拥有时效与签名验证。
- Discovery 请求/响应；GetPolicies 的 nil client/filter 与单 policy、固定 SHA-256 OID/group=1/name、nil CA 的响应；WSTEP Issue / RSTRC 的外层字段及 base64 CSR/provisioning。
- SyncML Get/Status/Results；初始化限定一个 Alert（1201 ClientInitiated 或 1224 LoginStatus）和一个 DevInfo Replace（DevId、Man、Mod、DmV、Lang 各一次，随后 Final）。Replace 只表示设备上报，不能用于服务端写设备。
- SOAP Fault 仅支持闭合集合及固定安全 Reason。decode 不保留外部 Reason 原文。编码不接受任意错误字符串。

未支持的 profile、命令、扩展节点/头、WBXML、签名或联合身份 token 明确拒绝，不以宽松模式继续。协议配置不是 Windows 版本/真机兼容认证。Opaque CSR/provisioning 测试字节不证明证书或内层文档有效。

## 公共使用边界

每个协议的 decode/encode 都接收 `CodecLimits`。SOAP decode 同时接收调用方选择的 `Operation`，Action 与 Body 必须匹配。字段按 namespace URI/local-name 匹配，前缀不是身份；SOAP Header 的已支持字段允许不同排列，XSD sequence 按序解析，Discovery 的 xsd:all 和 WS-Trust RST/RSTR 的集合字段允许重排，重复仍拒绝。Discovery 必须包含 OSEdition/AuthPolicies；客户端可声明多个已知认证方法，但必须包含 OnPremise。

`soap::decode_response(request, bytes, limits)` 从已验证的原请求推导正常响应或规范 Fault，单次解析 Action/Body 后完成关联。Fault 沿用原操作的输入字节预算，调用方不必预判 HTTP Body 是正常响应还是错误。严格指定 Operation 的 decode 仍可用于独立协议解码。

`soap::correlate(request, response, limits)` 验证响应类型、RelatesTo 与请求 MessageID，以及 WSTEP Context；返回带 must_use 的 `CorrelatedResponse`，区分 Discovery/Policies/IssueResponse 与 Fault。它不验证响应发送者身份或证明注册成功。

`syncml::encode_request(message, limits)` 仅编码服务端 Get/Status 消息，成功时同时返回 `(bytes, SentMessage)`；发送 token 的字段私有，保存实际编码的 SessionID、MsgID、命令类型和目标 URI 的不可变快照。调用方发送这批 bytes 后使用 `Expected::new(sent, response_message_id, limits)` 建立关联集合，`record_sent(sent, limits)` 只接受同会话、同端点且消息号未重复的 token；累计命令和条目受限，失败不改变原集合。关联不允许从响应反推 expected，修改原 Message 不改变已经生成的快照。

`syncml::correlate(expected, response, limits)` 使用上述封闭集合；产品仍负责认证注册、发送成功事实、跨响应累积和重放存储。编码成功不证明网络交付；禁止用未认证 Source/DevId 当作可信设备。codec 不定义 tenant/principal，不替代调用方的隔离。

1224 的类型固定为 `com.microsoft/MDM/LoginStatus`，封闭状态为 `user`、`others`、`none`，可省略 Format 或显式声明 `chr`；保留 Format presence，支持 Type/Format 两种顺序。一个 LoginStatus Item 纳入总条目预算。登录状态始终是未认证声明，不能据此授权用户配置。未知 Alert、payload、状态和扩展仍拒绝。

RSTRC 必须带 Timestamp；RequestID 使用可空有界字符串并保留 absent/nil/value，Disposition 同样保留可空字符串及可选语言；它们不参与认证。AdditionalContext 的 MAC/IMEI 可多值，逐值与总数均受限。

Results 的可选引用保留原始 presence；按 MS-MDM 的默认值 1 归一化后才精确关联。Status 的 CmdRef=0 单独关联 SyncHdr，不能引用普通命令。普通 Status 输出 MS-MDM 的 Data→Item→TargetRef→SourceRef 顺序；带 Cred/Chal 时输出 OMA 的 TargetRef→SourceRef→Cred→Chal→Data→Item 顺序。解码接受两种完整语法，拒绝混排。Chal 支持固定 BASIC 或 MD5 类型、Base64 二进制 nonce，明细保留为诊断数据；命令顺序按各原请求消息校验，允许当前消息头状态后附先前请求的剩余状态。重复、冲突、错会话/消息/命令/URI 拒绝；不会将 Results 压为覆盖重复键的 map。

合法部分响应返回 `Correlated { results, statuses, missing_results }`。statuses 保留非成功码，missing_results 保留尚缺的目标 URI。Final、成功 Status 或 missing_results 为空都不能单独证明跨消息采集完成；调用方必须结合所有状态、消息包完整性和自身 CollectionRun 判定。不提供布尔 success 捷径。

`Secret<T>` 通过显式 `.0` 访问载荷，Debug 只显示 REDACTED；这不提供内存加密或自动清零。调用方不得将解包后的凭据/CSR/provisioning/设备结果写入日志。`CodecError` 只携带闭合分类，不携带 XML、路径或原始错误链。`ForbiddenXml` 独立标识 DTD、处理指令、自定义实体（文本或属性）；`Unsupported` 表示未支持的协议能力，`MalformedXml` 表示语法错误。关联入口返回 `CorrelationError::{InvalidRequest, InvalidExpected, InvalidResponse, Mismatch}`：前三者分别保留本地请求、本地期望集合、远端报文的闭合 CodecError；Mismatch 表示合法报文的关联字段不匹配。多侧同时无效时先报告本地错误。

## 有界保证

默认值以 `CodecLimits::default()` 为唯一代码来源：Discovery 64 KiB、XCEP 256 KiB、WSTEP/SyncML 512 KiB；depth 32、elements 4096、events 16384、attrs/element 32、total attrs 2048、active namespace bindings 32、commands 256、items 1024、identifier 128 B、URI 2048 B、scalar 64 KiB、decoded binary 256 KiB。

所有限制始终生效，0 表示无容量。字节检查先于解析，结构计数先于累积，输出使用受限 Writer；base64 分配前检查编码长度，解码后核验精确长度。字段/命令和 pending expected 集合都受限。工作量用事件、节点、属性及集合上限控制，不依赖无法抢占同步解析的 timeout。调用方仍需在 HTTP 聚合请求体时限制字节与等待。

DTD/自定义实体、危险或非法 XML、未绑定/非法 QName、重复 expanded attributes、非法 UTF-8、多个根和 trailing content 均拒绝。XML 五个实体与合法数字字符引用被保留。只有预定义实体，不注册外部 resolver。

## 验证与证据

```sh
cargo test --locked -p rss-mdm-windows-mdm
cargo clippy --locked -p rss-mdm-windows-mdm --all-targets -- -D warnings
python3 -O -m unittest discover -s tests -p test_ci.py
```

完整验证在提交受测源码后执行本仓 `make ci`。它包含已有真实 PostgreSQL T2 和干净 Git consumer 验证，失败必须整体收集后集中修复。codec 的证明是 T1；产品 app 的真实签名、PG 与 HTTPS/mTLS T2 见 [Windows 接入指南](202609111146-2350-windows-enrollment-management.md)。Windows T3 独立实施。最终 HEAD、命令和 CI 结果在实现 PR 记录，本文不充当运行回执。

固定样本与来源见 [fixtures](../../crates/windows-mdm/tests/fixtures/README.md)。Rust 参考是 quick-xml 0.42.0 的 `src/reader/ns_reader.rs`、`src/events/attributes.rs`、`src/se/mod.rs`；低层事件读取不自动校验 QName 语法，私有词法检查对应 XML 1.0 第五版 Name/NCName 规则。时间格式解析使用 workspace 已锁定的 time 0.3.55。

关联凭据参考 oauth2-rs 5.0.0 `src/code.rs` 的 URL 与状态同时生成模式；错误来源参考 Rust `std::error::Error::source`，XML 拒绝分类参考 quick-xml 0.42.0 `src/events/mod.rs` 与 `src/escape.rs`。这不引入 OAuth 或额外依赖。

`provisioning::encode` 是有界纯内存输出，按 Full/Device 选择用户/系统证书库；证书、URL、秘密和 EntDMID 由已验证的产品流程提供。协议包不负责生成随机值或判定权限。
