# Agent V2 注册与报告接入

本指南描述 #2467 接入面在 #2468 后的当前行为，使用 `rss-mdm-agent-wire` 2.0.0 契约并提供真实 PostgreSQL 注册、Bearer 凭据认证、报告持久化、Observation 接收和 Inventory 投影接缝；不表示 `rss-mdm-agent` 已实现或真机采集已验收。

## 安装与版本边界

安装支持空库、精确的 a83f7876 基线或当前完整 ledger，条件与步骤见 [Agent V2 升级](../deployment/202609230002-2468-enterprise-task-upgrade.md)。旧 Agent 必须排空报告并撤销后重新授权注册，不接受旧凭据进入 V2。

管理 Enrollment API 已整体切换到 `/api/v2`，创建请求必须带 `channel: "agent"` 或 `channel: "mdm"`。`/api/v1/enrollments` 不再存在。Agent wire 独立固定为 `/api/agent/v2`，协议 major、capability、字段、状态和错误码均为闭合集；新增语义必须发布新 wire major。本次 V2 是未发布候选的直接替换，不保留旧候选 capability 或 result shape 的兼容路径。

## 注册

管理员先按 [Enrollment 与审计](202609090001-2347-enrollment-audit.md) 创建 `channel: "agent"` 的授权，并把 enrollmentId 与一次性口令安全交给设备。Agent 自行生成另一个 32 字节随机值作为长期 credential，然后发送：

```json
{
  "wireVersion": 2,
  "operationId": "非 nil UUID",
  "enrollmentId": "管理员返回的 UUID",
  "password": "43 字符无填充 Base64URL",
  "credential": "另一个 43 字符无填充 Base64URL",
  "capabilities": ["inventory.basic.v2"]
}
```

V2 capability 只允许两个有序集合：仅库存的 `["inventory.basic.v2"]`，或库存加企业任务的 `["inventory.basic.v2","task.execute.v2"]`。服务按请求原样持久化；两者均可提交基础库存报告，只有第二种可以通过任务 HTTP、事务内复核和生产目标选择。库存-only 注册访问任务返回 permission denied，也不会被静默升级为执行主体。

`POST /api/agent/v2/registrations` 仅接受 `Content-Type: application/json`，成功首次提交返回 201，精确重放返回 200；同 operationId 改变内容返回 409。绑定事务同时验证原管理员当前会话和 enrollment 权限、channel、口令版本、期限与世代，保存注册/来源/capability/成功审计并将 Enrollment 标为 bound。数据库只保存 tenant 域隔离的 SHA-256 locator，不保存 credential 明文。

同一设备再次完成 Agent 注册会建立下一世代并原子停用旧注册、旧 credential 和旧来源。MDM channel 世代相互独立。管理员撤销仍使用 `/api/v2/devices/{device}/registrations/{registration}/revoke` 和独立 `credentials` 权限。

## 报告与状态

报告请求使用严格的 `Authorization: Bearer <credential>`：

```json
{
  "wireVersion": 2,
  "reportId": "非 nil UUID",
  "sequence": 0,
  "observedAt": 1780000000,
  "body": {
    "kind": "snapshot",
    "values": [
      {"field": "device.model", "value": {"kind": "known", "value": "Model A"}},
      {"field": "device.os.version", "value": {"kind": "unsupported"}}
    ]
  }
}
```

V2 只接受 snapshot、partial、failed，不接受 delta。所有 UUID 使用小写 hyphenated 词法，`reportId` 在 tenant 内全局唯一；字段仅为 `device.model` 和 `device.os.version`；known 文本最多 256 个 Unicode 标量，snapshot/partial 中字段会规范排序，重复字段、未知字段、未知 JSON 成员和控制字符均拒绝。`POST /api/agent/v2/reports` 在不可变报告、摘要和成功审计提交后返回 202/durable；相同 reportId 与相同语义返回原 receivedAt，不同语义返回 409。

每个当前注册最多积压 32 条待投递报告；达到上限返回 `service_unavailable`，Agent 必须先重试既有 reportId。接受新报告前会通过 owner-only 窄函数把已投递历史裁至最近 224 条；运行角色没有表级 DELETE，不能删除 pending 报告。报告接收、幂等、容量与裁剪由同一 tenant/channel 事务锁串行化。Agent 与 Windows MDM 均由 `collection_runs` 持有不可变报告和最小交付进度，不存在第二套报告队列或 owner 分支。

恢复及 Agent 状态读取共同核对持久报告的 tenant、registration、source、epoch、dataset、reportId、sequence、coverage、规范字节和摘要，并要求报告已封存；数据库关系列与冻结报告内容不一致时拒绝恢复。

后台沿用唯一的 Inventory 运行时：持久报告恢复后提交 Observation，snapshot 可进入投影；partial/failed 形成 need-snapshot 决策而不投影。`GET /api/agent/v2/reports/{reportId}` 只允许当前有效 credential 读取当前注册/epoch 内的报告，返回 durable ack、Observation 状态与 Projection 状态。credential 被替换或撤销后，新报告和状态读取立即返回 401；替换前已提交的不可变报告仍可由后台恢复投递。

## 错误与验证

Agent 错误体固定为 `{ "code": "..." }`。不支持的 wire/capability、无效身份、报告不存在、幂等冲突、提交结果未知和依赖不可用具有独立闭合代码，不返回内部诊断或秘密。4-request permit 与 16 KiB streaming admission 在全量预缓冲前生效；17 KiB 与大于 2 MiB 的请求也只能得到闭合 wire 错误。

T1 由 `agent-v2.schema-manifest.json` 枚举全部 request/response/error shape，并锁定有序 schema fingerprint、双向语料、公开 producer 构造、严格 UUID/整数边界、规范化和秘密脱敏；`make t2-identity` 使用真实 PostgreSQL 与 HTTP Router 覆盖注册/重放、报告/并发重放/容量竞争/冲突、提交前 rollback、commit-unknown 恢复、完整错误矩阵、Observation/Projection 最终状态、partial/failed 不投影、worker 重启恢复、credential 换代及旧 V1 删除。仅在明确的消费者验收任务中，提交后手动运行 `make agent-wire-consumer` 从固定 Git SHA 与同一 SHA 生成的 `.crate` 候选包分别建立仓外 producer/response/error consumer，记录版本、schema fingerprint、archive SHA-256、依赖闭包和实际命令。全仓 CI 入口仍为 `make ci`，不包含模拟消费者。

协议形态参考 osquery Remote Settings/Distributed Read/Write 的分离思路，但本产品不复制其 TLS 配置或 query API：[osquery remote deployment](https://github.com/osquery/osquery/wiki/Remote-Settings-and-Distributed-Queries)。

企业任务、签名和扩展采集见 [#2468 指南](202609230001-2468-enterprise-tasks.md)。原 #2467 独立消费证明只覆盖当时的 V1 候选；V2 证据须绑定本次固定源码，不能沿用旧证明。
