# MDM Identity 接入

本项实现管理员身份消费、静态资源权限与资产查询。账户、本地密码、联合 IdP、JIT、中央会话由 rss-identity 拥有。运行证据以 #2343 的 PR 和受测 HEAD 为准；本文不表示候选或产品 T3 已通过。

## 唯一应用与依赖

`rss-mdm-app` 输出唯一生产 binary `rss-mdm`，提供 `serve --config FILE` 和 `migrate --config FILE`。
示例 binary 已更名 `rss-mdm-fixture`，只保留 ingest-fixture/project/inspect；旧 migrate 命令不保留。
产品不依赖 examples，迁移顺序只由产品应用维护。

RSS 主仓依赖固定同一完整 Git revision；Identity client/contracts 另固定 rss-identity 的完整 revision，精确值由 Cargo.toml/Cargo.lock 持有。CI 分别核对两种来源及公开包集合，不按 rss-* 前缀放宽来源。OIDC 复用 openidconnect；在线验证复用 IdentityClient，不存在自研 wire verifier、JWT 离线认证或认证缓存。

## 安装与运行配置

部署 owner 预建 mdm_owner、mdm_runtime、mdm_api 登录角色并分别配置密码。均不得是 superuser/BYPASSRLS 或通过角色成员资格取得更高权限。mdm_owner 持有目标数据库和 public schema CREATE；迁移依次安装 Observation、Projection、Inventory v1 与只读角色授权。既有 SQL 摘要不变；新 reader 授权只允许 mdm.inventory SELECT。运行服务只使用 mdm_api，worker 使用 mdm_runtime。

迁移配置只有 database 对象：host、port、name、user、password_file、ca_file；使用 mdm_owner。服务配置示例见 [配置样例](../../fixtures/mdm-config.example.json)，使用 mdm_api。配置与秘密为普通 0600 文件，禁止最终路径 symlink；CA 为可读取 PEM。示例中的域名和文件路径必须由部署 owner 替换，不是生产默认。

```sh
cargo run --locked -p rss-mdm-app -- migrate --config /private/mdm-migration.json
cargo run --locked -p rss-mdm-app -- serve --config /private/mdm.json
```

服务仅绑定回环地址，反向代理提供 HTTPS，并保留配置中的精确 Host；不要开放直连后端。`product_origin` 必须与 Identity 注册的 product origin/callback 一致；OIDC issuer 使用已注册的公共 issuer。`identity.origin` 是后端可达的私有验证 HTTPS 入口，`identity.issuer` 是 OIDC 公共 issuer；分别保证 DNS/路由/CA 正确，不通过反代重写 issuer。私有验证端点只能向已注册产品服务暴露，公有 OIDC 端点必须可被后端访问；不得让私网 DNS 路由遮蔽 OIDC discovery/token/JWKS。

配置启动时完整验证，改角色、设备范围或来源后重启。当前为单实例；重启清空本地会话，浏览器持旧 cookie 时开始登录会清理旧句柄并重新认证。无角色绑定的用户可经 /api/v1/auth/me 获取自己的 pairwise subject，由 MDM 管理员写入映射；Identity 管理员不会自动获得 MDM 角色。

## HTTP 契约

| 方法 / 路径 | 行为 |
| --- | --- |
| POST /auth/login | 精确 Origin、X-MDM-Request: 1；已有有效产品会话另需 X-CSRF-Token。返回 authorization_url。 |
| GET /auth/callback | 绑定浏览器的单次 state；Code+PKCE、ID token 与在线验证通过后旋转 cookie，303 到 /api/v1/auth/me。HEAD 不执行兑换。 |
| GET /api/v1/auth/me | 每请求在线复核，返回 subject/tenant_id/client_id/roles/csrf_token/expires_at；不返回 protocol token。 |
| POST /api/v1/auth/logout | Origin、X-MDM-Request: 1、CSRF；删除本地产品会话并清 cookie。Identity 不可用时仍可退出；不是中央 logout-all。 |
| GET /api/v1/devices/{id}/inventory?registration=…&source=…&epoch=… | 五种既定角色及显式设备范围；按完整来源坐标查询，不合并来源/注册世代。不接受 tenant 参数，无数据404。 |
| POST /api/v1/devices/{id}/actions | 额外要求 super_admin/mdm_admin、allow_wipe=true、设备范围、Origin/请求标记/CSRF；只识别 {"action":"wipe"}，无权403，有权501 action_not_supported。 |

所有响应 no-store/no-referrer。无效身份401，权限/CSRF拒绝403，输入错误400，依赖/服务凭据/协议错误503。响应和日志不输出 SQL/provider 原文或凭据。默认请求预算10秒、在线验证5秒，body最多16KiB、URI最多8KiB。

Cookie为 `__Host-mdm-session`，Secure、HttpOnly、SameSite=Lax、Path=/、无Domain。浏览器只保存随机句柄；协议凭据存有界内存。最多10000个会话、1000个待完成登录，登录期限300秒，容量满拒绝新建、不驱逐有效会话。

每个业务请求调用SDK得到当前VerifiedIdentity，MDM policy构造请求级授权凭证后才访问reader。handler不能取得PG pool或构造裸tenant查询。reader在同一事务设置RLS tenant并限定完整scope。租户身份来源仅为可信结果，所有调用失败均不得沿用上次身份。

Identity失效提交后开始的验证拒绝；已验证在途请求不追溯取消。MDM调用不续中央idle，不自动刷新token；到期重新授权。静态角色变更通过重启生效。危险动作501不会产生命令、Outbox或执行成功审计。
