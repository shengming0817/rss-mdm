# MDM 内嵌认证与产品授权

#2437 将认证直接装配到 `rss-mdm`。MDM 持有实例、租户、数据库角色、秘密和生命周期；账户、密码、会话、OIDC 协议及安全事件由 Identity 四个公开组件持有。产品授权规则、设备范围、管理与发布许可由 MDM 持有。

RSS 全部依赖固定同一个完整 revision；`rss-identity-core`、`rss-identity-postgres`、`rss-identity-http-axum`、`rss-identity-oidc` 固定同一个 Identity revision。具体版本由 Cargo.toml/Cargo.lock 持有。产品不运行 Identity 参考应用、中央验证服务或 Hydra。

## 新实例安装

使用 PostgreSQL 17。管理员先创建 `mdm_owner`、`mdm_runtime`、`mdm_api`、`mdm_access`，再应用 `crates/app/schema/` 下的角色 SQL；为实际登录角色设置独立密码。各角色均不得具有 superuser/BYPASSRLS 或继承高权限角色。`mdm_owner` 需要数据库及 public schema 的 CREATE 权限；它可切换到 Identity 两个 profile 以验证权限，两个 profile 不继承 owner。

`mdm_api` 仅供 Inventory PG 公共 reader 的独立消费与 T2 验证，不进入 serve 配置或生产装配。统一资产查询使用 `management.database` 的事务。

迁移输入为 `database` 与 `installation`：后者包含规范 UUID `instance_id`、16 字节 `target`/`lineage`、正整数 `epoch` 和显式租户 UUID 数组 `tenants`。安装当前完整 RSS schema、产品不可变迁移和 Identity v11，并持久保存安装坐标。重放核对迁移摘要、实例、存储坐标、租户 epoch 和 runtime/maintenance 权限。

只接纳空库安装或完全匹配的新实例重放。非空旧账本、缺失或不同摘要、实例/存储/角色不匹配均拒绝；不改历史 SQL，不回填旧 Outbox，不删除数据来通过检查。

```sh
rss-mdm migrate --config /private/migrate.json
rss-mdm initialize --config /private/initialize.json
rss-mdm initialize-authorization --config /private/authorization.json
rss-mdm serve --config /private/mdm.json
```

初始化输入包含 `database`（`mdm_identity_maintenance`）、同一 `installation`、`tenant_id`、预先选定的 `principal_id`、`login` 和 `password_file`。将这个主体明确写入独立的 `identity_management` 配置，`permissions` 为 `["accounts", "providers"]`。每个租户仅初始化一次；日常账户创建、改密、停用和 IdP 管理使用受保护的组件 HTTP 接口。

紧急恢复使用 `rss-mdm recover-password --config FILE`，配置同上但 `login` 为 null，目标为现有主体。恢复通过组件 maintenance API 轮换凭据并撤销旧会话；maintenance 凭据不进入服务进程。配置和秘密使用普通 0600 文件，禁止末级路径 symlink；CA 使用可读 PEM。

## 运行配置与边界

[服务配置样例](../../fixtures/mdm-config.example.json) 中 `identity` 只有 `instance_id`、`tenant_id`、`database`、可选 `oidc`。认证数据库必须与 MDM 业务库同址，角色为 `mdm_identity_runtime`。`oidc: null` 时启动、本地登录、刷新和退出只访问自有 PG，不进行 IdP discovery 或其它远程认证调用。

管理监听器仅绑定回环地址。HTTPS 网关覆盖 X-Forwarded-For；后端先通过 RSS listener 提供的实际 TCP peer 核对 `trusted_gateway`，再接受唯一的客户端 IP，移除转发头后向组件传递 `ClientAddress`。不要开放绕过网关的入口；多级代理须重新定义可信来源。

每个受保护业务请求都获得新的 `AuthenticatedSession`，再检查 `(instance, tenant, principal)` 和产品许可。浏览器输入不能构造可信身份，成功验证结果不缓存。宿主统一调用组件 `authenticate_request`：被动 GET/HEAD 选择 Passive，不延长 idle；写请求选择 Active，由组件检查精确 Origin、`X-Identity-Request: 1` 和 CSRF。cookie 格式错误、重复或超限均返回 400；MDM 不维护另一套解析器。凭据 cookie 为组件的 `__Host-identity-session`，使用 Secure、HttpOnly、SameSite=Lax、Path=/、无 Domain。

组件操作使用自身 10 秒预算；宿主先有界读取请求体，业务操作在认证完成后执行其 8 秒预算，收尾审计另有 2 秒。组件提交结果不被宿主外层 timeout 丢弃。全局业务并发上限 4；密码 KDF 和登录尝试另由组件控制。PG 不可用时认证与注册拒绝，不使用既往成功结果兜底。

## 产品权限

MDM 业务和授权管理使用持久化规则，每次请求读取当前规则与本地用户组的一致快照。规则支持精确用户、IdP 安全组、部门 exact/subtree、本地显式成员组；每项授权独立绑定 operation 与 scope，默认拒绝，不推导角色、不拼接不同规则的操作和范围。规则或成员提交后下一个请求生效，不需重启。接口、来源有效期与操作流程见 [#2363 授权指南](202609200002-2363-authorization.md)。

`identity_management` 仅管理 Identity 账户和 provider，配置每项包含 instance_id、tenant_id、principal_id、permissions（accounts/providers）。它不授予 MDM 业务权限。组件策略强制同实例同租户、敏感操作最近 300 秒认证，并禁止停用配置中的账户管理员或移除其成员资格。自助改密仅限本人。

## HTTP 接口

原生认证契约由固定版本组件持有，不另建 MDM 账户 DTO。

| 方法与路径 | 作用 |
| --- | --- |
| POST /api/v2/tenants/{tenant}/login | 本地登录，返回组件会话信息及 csrfToken，凭据只在 cookie 中 |
| GET /api/v2/tenants/{tenant}/session | 被动读取当前会话 |
| POST /api/v2/tenants/{tenant}/session/refresh | 旋转会话凭据，旧凭据失效 |
| POST /api/v2/tenants/{tenant}/session/logout | 撤销当前会话 |
| POST /api/v2/tenants/{tenant}/sessions/logout-all | 撤销该账户全部会话 |
| /api/v2/tenants/{tenant}/accounts | 受保护的组件账户管理 |
| GET /api/v1/authorization | 产品投影 instanceId/tenantId/principalId、有效 grants 与来源 |
| GET /api/v1/devices/{id}/inventory | 检查设备范围，通过当前有效注册选择坐标 |
| POST /api/v1/devices/{id}/actions | 检查显式 wipe 许可，当前返回 action_not_supported |

## 可选企业 SSO

OIDC 配置包含 `state_key_file`、`active_credential_key`、`credential_keys`、`group_facts_max_age_seconds`、`return_targets` 和 `assurance_profiles`。状态与凭据加密 key 文件各为 64 位十六进制；返回目标由宿主明确列出。provider 通过组件管理路由 `/api/v2/tenants/{tenant}/providers` 创建、测试和启停，client secret/私有 CA 由组件加密持久化。

回调固定为 `product_origin + /api/v2/oidc/callback`，也必须精确注册到 IdP。生产传输接受 HTTPS 公网单播及宿主 `private_providers` 明确授权的私网目的地；不得将测试 loopback transport 当成生产配置。assurance profile 精确绑定 tenant/issuer/client，只有部署 owner 已核实 Keycloak 密码/TOTP LoA 2 流时才设置 `keycloak_totp: true`。

外部 subject 是不透明字符串，身份以 issuer 与 subject 精确绑定，邮箱不自动关联。已有账户通过本人认证及组件显式关联流程接入；step-up 旋转所绑定会话。provider 停用使其既有联合会话失效；IdP 故障不阻断本地认证。

## 注册凭据引用与退出边界

Windows 注册交接只持有最长 300 秒、容量 10000、秘密可零化的凭据引用缓存。它不签发会话、不续期、不保存验证成功证明。每次后续请求以引用找到组件凭据，再权威验证主体和设备许可；签发提交前再次检查。注销、撤销、轮换、账户/成员停用、PG 故障均阻断后续注册。

旧中央主体坐标为 tenant/client/pairwise subject；新坐标为 instance/tenant/principal UUID，两者不自动对应。新实例重建账户，不导入主体映射；旧审计保留历史含义，旧会话和非终态业务不续接。新进程不读取旧 cookie，也没有旧 cookie 清理、双读或自动回退。需要回退时停止新部署，再恢复独立的旧部署与其数据库。

`make t2-identity` 先仅运行自有 PG 的本地认证、账户管理、设备/管理/发布授权、审计、幂等与故障拒绝，再启动独立企业 Keycloak 验证 callback、关联、step-up 和故障隔离。`make t2` 验证真实 Windows/PG/Inventory 接缝。完整门禁为提交受测源码后的 `make ci`；候选和生产 T3 各自提供独立证据。

## 浏览器宿主与私网接入（#2364）

OIDC 配置必须含 `private_providers`，仅公网显式填写 `[]`。每项为
`{"tenant_id":"本产品租户 UUID","issuer":"https://idp.example.test:8443/realms/mdm","client_id":"mdm","cidrs":["10.20.0.0/24"]}`。
网络授权仅由宿主配置持有；租户管理 API 不可修改。租户须匹配本产品，组件统一校验精确 issuer/client、规范 CIDR、全部 DNS 地址和证书；loopback、link-local/metadata、保留地址不可授权。网络许可不授予 MFA 或业务权限。

UI 使用 rss-web 独立认证镜像。唯一产品网关 `deployment/nginx.conf` 同源承载 SPA、组件和业务 API，挂载 `/run/config/ui.json`：
`{"canonicalOrigin":"https://mdm.example.test","oidcEnabled":true}`。API 未命中不回退 SPA。
`GET /api/identity-host/v1/tenants/{tenant}/context` 被动核验权威会话，返回 tenantId/principalId/sessionId 与 navigation.manageAccounts/manageProviders；未配置 Identity 管理许可的合法用户两个提示均为 false，错误租户拒绝。提示不代替真实请求授权。

PG 故障时授权拒绝，退出也无法确认撤销；UI 不得报告成功。PG 恢复后服务端仍以实际持久状态为准，需重新确认并完成退出。新候选仅接受全新 v11 安装或同候选重放；不提供旧库转换、配置别名或认证回退。独立浏览器入口与证据见 [#2364 验收](../deployment/202609190000-2364-authentication-t3.md)。
