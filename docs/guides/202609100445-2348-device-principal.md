# I01 设备身份与报告边界

适用范围：#2348 的 I01 核心；Windows 真实证书、注册 HTTPS 与管理 mTLS 已由 [#2350/#2351 接入](202609111146-2350-windows-enrollment-management.md) 消费。本指南不代表真机 T3 完成。

## 更新与配置

在停止旧进程后，用既有 mdm_owner 迁移入口安装追加的 device-identity-v1 单元，再启动新进程。旧迁移摘要保持不变；不删除迁移记录、身份历史或审计来强行通过 admission。不支持旧二进制与新 schema 混跑。

所有 binding 新增必填 allow_manage_credentials，默认部署填写 false。只有 super_admin/mdm_admin 和明确设备范围可以启用。管理员注册许可与凭据管理互不继承。

## 当前资产查询

`GET /api/v1/devices/{device}/inventory?source=mdm.windows`

Agent 来源选择为 `source=agent.builtin`，仅存在相应可信注册和数据时返回资产；这不是 Agent 设备接入已完成的声明。旧 channel 与 registration、epoch、tenant 查询参数一律拒绝。响应包含 tenant_id/device_id/registration/source/epoch/coverage/fields；同一接口只返回选定来源，未知或已失效的当前映射返回 404；未知 source 返回 400，有效注册尚无投影值返回 200 unavailable。完整响应与恢复语义见 [Windows 资产采集](202609120000-2352-windows-inventory.md)。

没有持久设备映射的历史 fixture 数据不会出现在当前查询中。F01 CLI 仍用于库组合验证，不接入产品 HTTP 授权路径。

## 内部 gateway 接缝

Windows 绑定使用当前已验证管理员、Enrollment request、可信叶证书、稳定内部签发操作 ID 与创建时冻结的世代；管理员无需填写 expected_generation。底层 I01 仍用世代比较保障并发替换。Conflict 要检查操作身份或并发变化，不得擅自把未知提交换成新键。成功回执是原操作事实，不能当作当前凭据有效性证明。

bind/revoke 在提交开始后的超时返回 CommitUnknown，调用方保留原 operation_id 重试恢复；只有尚未开始提交或已证明未提交时返回普通 deadline。回放已有回执仍检查当前权限。

报告保留相同 Scope/batch_id 重传，同键异内容冲突。重注册生成新 registration/epoch，旧已准入报告只能进入历史 Scope。手工撤销同时失效凭据、注册和来源授权。

管理消息与 CollectionRun 终结均持久审计；精确响应重放不创建新 run。持久审计不可用或收尾取消时，fallback 事件保留已知 registration_id 以关联注册世代，不输出 actor/client/target 或通道凭据。

## 验证

- `cargo test --locked -p rss-mdm-app --lib`：模型与权限。
- `cargo test --locked -p rss-mdm-app --doc`：可信类型无法由 DTO 或裸指纹构造。
- `make t2`：真实 PG 事务、幂等恢复、换代隔离与 Observation/Inventory 组合；入口显式启用 integration 故障注入 feature，普通构建保持关闭。
- `make t2-identity`：真实管理员 Identity 接线；不作为设备证书证明。
- 提交受测源码后 `make ci`：本地完整入口，证据位于 artifacts/local-ci，结果绑定 HEAD。

测试专用 Identity 响应服务只由 hack/device_t2.py 启动，通道 proof 只存在于 Rust 单元测试构建；不得将二者部署或描述为设备认证实现。缺 Docker/PG/Identity 前提时对应 gate 失败，不跳过后报绿。
