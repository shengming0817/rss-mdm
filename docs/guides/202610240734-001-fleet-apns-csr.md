# 通过 Fleet 在线接口签署 APNs CSR

本指南用于由 RSS 保管 APNs 私钥、向 Fleet 提交公开 CSR，并由管理员到 Apple 门户取得最终推送证书。Fleet 的在线签署依赖其服务可用性和接受条件；开源代码不包含可供使用的厂商私钥，也不构成为其他 MDM 产品提供服务的承诺。

## 材料与保管

仓库根目录的 `apns_certs/` 用于当前部署的本地材料，已被 Git 忽略。目录权限设为 `0700`，文件设为 `0600`；不要使用 `git add -f`，备份通过独立受控介质完成。

| 文件 | 用途 |
| --- | --- |
| `apns-private.key` | 原 APNs RSA 私钥的受控备份，不上传至 Fleet 或 Apple 门户 |
| `apns-original.csr` | RSS 原材料版本的普通 PKCS#10 CSR |
| `apns-fleet.csr` | 用同一私钥生成、满足 Fleet 主题约束的普通 CSR |
| `apns-fleet-signed.csr` | Fleet 返回的 Base64 编码 Push Certificate Request，提交 Apple 门户 |
| `apns-cert.pem` | Apple 门户最终签发的 APNs 叶证书 |
| `apns-chain.pem` | 叶证书及其 Apple 中间证书、根证书链 |
| `fleet-vendor-cert.pem`、`fleet-vendor-chain.pem` | 验证厂商签名所用的公开证书，不是 RSS 的 APNs 推送证书 |
| `manifest.json` | 本地材料摘要、原密钥版本、推送 Topic 与到期信息 |

RSS 的运行私钥由 Apple 材料 owner 加密持久化。导出的文件只供已授权维护备份；运行配置不恢复私钥文件加载。备份与恢复须同时保留数据库及其保护材料，不能只备份公开证书。

## 用现有私钥生成 Fleet CSR

按真实申请主体填写组织名称和组织邮箱。Fleet 签署器要求 Subject **恰好只有 Organization 和 emailAddress 两项**；不得保留普通 CSR 的 CN，也不要增加 C、OU 等字段。多余字段会使签署失败，网站可能只返回 HTTP 500。

在仓库根目录执行，替换示例组织和邮箱：

```sh
umask 077
openssl req -new -sha256 \
  -key apns_certs/apns-private.key \
  -subj '/O=Example Organization/emailAddress=admin@example.org' \
  -out apns_certs/apns-fleet.csr
openssl req -in apns_certs/apns-fleet.csr -noout -verify -subject
```

这只重签 CSR，不生成新私钥、不撤销旧证书。确认 CSR 与原密钥的公钥一致；密钥来源必须是目标 RSS 租户的原材料版本，不能使用 Intune 等其他服务的 CSR 所对应的未知私钥。

## 请求在线签署

Fleet 客户端采用 `POST https://fleetdm.com/api/v1/deliver-apple-csr?deliveryMethod=json`；正文 `unsignedCsrData` 为 **PEM CSR 整个文件的 Base64**。不包含私钥，返回 JSON 的 `csr` 也是 Base64 编码的字节字段。

以下命令只提交一次，并保存原始回执；先检查旧回执，不因超时、未知结果或 5xx 自动重复申请：

```sh
python3 - <<'PY'
from pathlib import Path
import base64, json, os, urllib.error, urllib.request

os.umask(0o077)
p = Path('apns_certs')
receipt = p / 'fleet-response.json'
if receipt.exists():
    raise SystemExit('已有回执；核对原结果后再决定是否发起新的请求')
body = json.dumps({
    'unsignedCsrData': base64.b64encode((p / 'apns-fleet.csr').read_bytes()).decode()
}).encode()
class NoRedirect(urllib.request.HTTPRedirectHandler):
    def redirect_request(self, *args, **kwargs):
        return None
opener = urllib.request.build_opener(urllib.request.ProxyHandler({}), NoRedirect())
request = urllib.request.Request(
    'https://fleetdm.com/api/v1/deliver-apple-csr?deliveryMethod=json',
    data=body, method='POST',
    headers={'Content-Type': 'application/json', 'Accept': 'application/json',
             'User-Agent': 'RSS-MDM-CSR-client/1.0'},
)
receipt.write_text(json.dumps({'status': 'attempting'}))
try:
    with opener.open(request, timeout=45) as response:
        status, raw = response.status, response.read(1024 * 1024)
except urllib.error.HTTPError as error:
    status, raw = error.code, error.read(1024 * 1024)
except OSError:
    receipt.write_text(json.dumps({'status': 'unknown_transport_outcome'}))
    raise SystemExit('结果未知；保留原 CSR，不自动重试')
receipt.write_text(json.dumps({'httpStatus': status, 'body': raw.decode(errors='replace')}))
if status != 200:
    raise SystemExit(f'HTTP {status}；未取得签署结果，查看本地回执')
result = json.loads(raw)
(p / 'apns-fleet-signed.csr').write_bytes(base64.b64decode(result['csr'], validate=True))
print('已保存厂商签署申请；尚未取得 Apple APNs 证书')
PY
```

`deliveryMethod=json` 返回结果不依赖邮箱收件；组织和邮箱仍接受 Fleet 的校验及域名限制。这个接口不签发最终 APNs 证书。

## 验证签署结果与 Apple 签发

提交 Apple 前须验证以下内容：

1. 对 `apns-fleet-signed.csr` 做 Base64 解码，按 plist 解析 `PushCertRequestCSR`、`PushCertCertificateChain`、`PushCertSignature`。
2. `PushCertRequestCSR` 解码后的 DER 必须与 `apns-fleet.csr` 的 DER 完全相同，不只比较名称。
3. 使用厂商叶证书公钥，对该 DER 验证 RSA PKCS#1 v1.5 / SHA-256 签名。
4. 将厂商证书链验证到从 [Apple PKI](https://www.apple.com/certificateauthority/) 独立取得的受信根，同时检查有效期；不能仅信任响应自行携带的根。

管理员登录 [Apple Push Certificates Portal](https://identity.apple.com/pushcert/)，上传的是 **Fleet 签署后的文件**，不是普通 PEM CSR。首次申请创建证书；续期选择原证书记录的 Renew，核对原 Topic，避免创建新的推送身份。下载的 `.pem` 保存为 `apns_certs/apns-cert.pem`。

最终证书必须与原私钥公钥一致；按证书实际 issuer 从 Apple PKI 获取中间证书，不把 Fleet 的 WWDR 厂商签署链当作 APNs 叶证书链。可将公钥分别导出后比较：

```sh
openssl pkey -in apns_certs/apns-private.key -pubout > apns_certs/key-public.pem
openssl x509 -in apns_certs/apns-cert.pem -pubkey -noout > apns_certs/cert-public.pem
cmp apns_certs/key-public.pem apns_certs/cert-public.pem
openssl x509 -in apns_certs/apns-cert.pem -noout -subject -issuer -dates
openssl verify -CAfile apns_certs/apple-root.pem \
  -untrusted apns_certs/apple-application-integration-2.pem apns_certs/apns-cert.pem
```

最后一行以 issuer 为 Apple Application Integration 2 的证书为例；其他 issuer 应选择对应中间链。Topic 来自 APNs 证书 Subject UID，不来自文件名、CSR 的 Organization 或 Fleet 的 Team ID。

拼接完整链时，每个 `END CERTIFICATE` 与下一个 `BEGIN CERTIFICATE` 之间必须保留换行；Apple 下载的叶证书可能没有结尾换行。可用 `openssl crl2pkcs7 -nocrl -certfile apns_certs/apns-chain.pem -outform DER -out apns_certs/apns-chain.p7b` 检查整份 PEM 能否解析。

## 导入 RSS 与验收

经正常 Apple 材料 API 将证书导入 **原 key revision**；CSR 的 Subject 改动不要求替换密钥版本。若 RSS 当前版本保存的是原 CSR，其公钥仍与新 CSR 和最终证书一致。

当前 APNs 推送消费者按单张 PEM 解析叶证书：APNs 用途提交 `apns-cert.pem`，由部署 owner 在 `apple_material_roots` 中同时提供已核验的 Apple 根和对应中间证书，完整链另外留档。仅材料导入验证通过不能证明包含多张 PEM 的内容可被推送消费者加载。Profile 签名用途独立管理，不套用此 APNs 输入限制。

按照 [Apple 管理](apple-management.md#产品配置) 和[部署运维](../deployment/operations.md)配置认可的材料根、独立 Profile 签名身份、选择版本、准备宿主并受控重建。APNs、Profile、网站 TLS 和设备 SCEP 身份分别管理；不修改生成文件伪造已应用，也不绕过证书校验。

证书签发、导入、宿主已加载与设备效果分别记录。只在指定 macOS 测试机上完成系统注册确认、SCEP/mTLS、TokenUpdate、APNs 唤醒、原生采集和配置实际安装/移除后，才能声明相应 MDM 场景通过。仅 Fleet 返回 200 或 Apple 发证不代表这些场景已通过。
