# Windows 资产采集与查询

#2352/#2353 在已有 Windows 管理通道中采集设备型号与系统版本。每个完成双向 SyncML 认证的新会话创建一个 CollectionRun；没有手工重采、调度、历史列表或 Agent 入口。

## 采集与恢复

| Get URI | Inventory 字段 |
| --- | --- |
| ./DevInfo/Mod | device.model |
| ./DevDetail/SwV | device.os.version |

Inventory 核心唯一持有字段键和 UTF-8 值规则；Windows adapter 以穷举映射绑定 URI，命令数量、CmdID 范围、累计字段槽和完整性判定从同一目录派生。型号与版本均需非空、最多 256 字节且不含控制字符。非法值仅保存诊断摘要，不能通过长输入放大持久记录。

管理会话按 challenge、collecting、complete 推进，延续最多 8 条消息与 15 分钟窗口。Get 的 MsgRef、CmdRef、URI 必须精确关联已保存的请求；字段可以分消息返回。Final 表示该消息结束，不能证明完整采集。两个字段均有成功 Status 和有效 Results 才封存 Snapshot；有部分有效值为 Partial；明确失败或无有效值的设备报告为 Failed。Partial/Failed 不覆盖既有资产。没有设备字段响应的纯超时仅终结 run，不制造 Observation 报告。

每个会话实例使用独立 UUID 作为 run/batch ID，sequence 在同 Scope 内递增。Get CmdID 在 registration/source epoch 内递增且不回绕，SessionID 清理后重用也无法关联旧结果。相同消息只重放已提交响应，同号不同内容返回冲突。接受片段时在事务内按 registration、credential、source 顺序复核授权，片段、协议状态、精确响应与审计一起提交。

终结时冻结 Scope、batch ID、sequence、规范字节、指纹和时间。数据时间基于服务器实际收到字段响应的时间；finished_at 单独表示终结时间，超时不会把旧字段伪装成此刻采集。设备未声明可信测量时间。

CollectionRun 自身是持久接入记录。后台仅恢复其中已封存的原报告，并交给 RSS Observation 的 activate/receive；不另建报告队列。后续吊销或换代拒绝新输入，已接受的历史输入可以终结封存并恢复至原 Scope。恢复入口统一验证关系行的 tenant、registration、source、epoch 与封存 Scope 一致，并验证 Inventory dataset、batch 与指纹。该授权不能创建任意 batch，也不能变更内容。提交未知保留原报告；lookup 未找到不能证明回滚。

Observation 独占 receipt、重放冲突与 journal。应用直接组合 PgSource、既有 Inventory PgEffect 和 RSS Projection runner；Inventory 与 checkpoint 同事务提交。receipt 与投影完成是独立事实，进程退出后从原持久记录继续。journal、投影 generation 与 definition 由 inventory-postgres 唯一持有，读写侧及示例共享；投影状态通过 RSS 公共 receipt_status 查询取得。worker 失败在关键任务退出前输出 mdm_inventory_failure 和封闭 phase，不记录 provider 正文或凭据。

## 查询契约

管理员每次查询均通过现有 Identity 在线验证和产品设备范围授权：

~~~text
GET /api/v1/devices/{device}/inventory?source=mdm.windows
GET /api/v1/devices/{device}/collection-runs/{run}?source=mdm.windows
~~~

source 是封闭枚举，由服务器派生 channel。旧 channel 参数及调用者指定的 tenant、registration、epoch 均拒绝。agent.builtin 仅允许选择已经存在的注册来源，不表示已有 Agent 接入。

资产查询复读 run 和投影字段，验证两者在 receipt 查询前后保持相同版本；最多尝试三次，持续变化时返回 503。资产响应按字段目录固定包含两个字段槽。last_good 只来自已提交投影，包含 value、batch_id、reported_at、received_at；latest_attempt 包含 run_id、quality、协议 status、实际接收时间和 server_received 时间基准。latest_run 说明 result、reason、sequence、started_at 和 finished_at。delivery 分别给出实际 receipt 与 projected/pending/pending_receipt/not_applicable 状态。

| availability | 含义 |
| --- | --- |
| current | 最新完整 run 已投影，两个字段均对应该 batch |
| last_known | 存在已投影值，本轮尚未形成当前完整资产 |
| unavailable | 当前注册有效，但尚无已投影值；返回 200 |

没有当前授权来源映射返回 404；未知 source 或旧参数返回 400。run 查询仅在当前选定 Scope 内解析指定 UUID，找不到返回 404，不接受任意历史坐标。所有查询与拒绝均审计，普通 GET 记录 success 且不声明幂等操作；不可持久化的目标值不进入审计 target。审计失败返回 503 和安全告警。

## 验证边界

T1 覆盖字段累计、完整性、非法值、冲突及纯超时。真实 PG/mTLS T2 覆盖分片、精确重放、提交未知、吊销后的原报告恢复、跨租户读取拒绝、投影事务失败和重启。F01 保留其独立的 RSS 接缝测试，生产应用不依赖 examples。

候选构建与实际进程验收见 [Linux arm64 部署](../deployment/202609120000-2353-linux-arm64.md)。这些证据不替代 Windows 真机 T3。
