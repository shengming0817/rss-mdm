# 授权管理 API 与持久计划

#2390 在现有 `rss-mdm-app` 中组装 Group、Scope、Policy、Resource 和软件发布。
核心与对应 PG adapter 保持独立，应用拥有真实管理员权限、资产来源解释、跨 owner 引用和事务审计。
这里只生成计划和后端源发布事实，不向设备派发，不产生 Applied/Converged 或安装成功证据。

## 配置与全新安装

服务配置见 `fixtures/mdm-config.example.json`。管理动作由 [#2363 持久化规则](202609200002-2363-authorization.md) 显式授予，scope 必须为 tenant；共享组不按操作者设备范围截断。管理授权不会授予设备注册、凭据撤销或资产 API 权限。

管理连接 `mdm_management_runtime` 与外部发布连接 `mdm_software_driver` 分离；两者都必须连接同一产品数据库。
`management.target`、`lineage`、`epoch` 必须与现有 RSS storage lineage / tenant epoch 相符，由部署 owner 明确设置，不能从请求推导。
管理角色使用 SERIALIZABLE 短事务。计算固定已提交资产水位，逐页读取对应历史，不跨页持有事务；并发失败沿原操作身份恢复。
运行角色不得拥有 DDL、超级用户、BYPASSRLS 或其它业务凭据读取权；启动检查 schema、RLS、实际权限和组件 catalog。
资产与注册只读事务不请求行写锁，也不授予 UPDATE 权限；管理对象的引用保护依赖 SERIALIZABLE 与 owner 提供的事务接缝。
启动总预算为基础 35 秒，加发布连接 5 秒和每个配置源 6 秒；最多 16 源，来源连接失败保留独立诊断类别。
连接取得后立即注册到现有生命周期，listener 关闭后再关闭池；启动失败不能进入 readiness。

全新部署按顺序安装 `crates/app/schema/software-publication-roles.sql`、`management-roles.sql`、`identity-roles.sql`，由管理员配置独立登录秘密，再以 mdm_owner 执行 `rss-mdm migrate --config <migration.json>`。当前 固定摘要单元（以二进制 --describe 为准）包含完整 RSS schema 与 Identity v11；同址的组件 runtime/maintenance 角色分别核验。既有产品 SQL 摘要不改写，仅空库安装或精确重放，旧清单、损坏或不完整账本拒绝且保留数据；执行步骤见[命令服务前向升级](../deployment/202609210000-2465-command-upgrade.md)。安装配置必须明确实例、存储和全部租户；设备标识仍为 1–256 UTF-8 字节、不含控制字符。

`management.sources` 是显式源配置列表；空列表表示没有被配置的私有源，源管理请求返回不存在。
每项提供 name、test/pilot/production 三个独占物理源、公开产物 origin/IP/CA 和 max_artifact_bytes。
WinGet/Brew 的底层源格式见[发布指南](202609132008-2388-2389-backend-persistence.md)。HTTP 请求不能添加地址白名单或提交源凭据。

## HTTP 契约

Group、Scope、Policy 路径前缀为 `/api/v2`；Resource 和软件源发布路径仍为 `/api/v1`，使用组件原生会话、每请求权威验证、Origin/CSRF 和 16 KiB 请求体上限。
路径中的 ID 必须正确 URL 编码。管理 HTTP 请求/响应字段统一 camelCase，未知请求字段拒绝；不接受旧 snake_case 字段。配置文件的权限名称与数据库内部文档格式独立于 HTTP 契约。写入统一为：

```json
{"operationId":"非零UUID","expectedRevision":1,"input":{"action":"..."}}
```

operationId 绑定 tenant、真实操作者、client、对象和完整输入。提交未知时重发原请求，不更换 ID 或预期版本；更改输入返回 409。
响应包含 `x-request-id` 供审计关联。写入成功审计与业务状态同事务；查询/拒绝审计失败返回 503，不返回未审计的数据。
401/403 沿用既有身份与权限错误；400/422 为无效输入；409 为版本、引用、不可变身份或状态冲突；503 为依赖失败或提交未知。

| 路径 | 能力 | 权限 |
|---|---|---|
| GET/POST `/groups/{uuid}` | 读取定义/成员；create、edit、rule、members、delete、recompute | group_read / group_write；重算为 group_recompute |
| POST `/groups/{uuid}/previews` | 异步规则预览，input 为 `{}` | group_read |
| GET `/groups/{uuid}/tasks/{task}` | 组计算进度与安全失败类别 | group_read |
| GET `/scopes/{uuid}/tasks/{task}` | Scope 计算进度与安全失败类别 | scope_read |
| GET/POST `/scopes/{uuid}` | 读取；put、delete，定义版本 CAS | scope_read / scope_write |
| GET/POST `/policies/{id}` | 读取；create、activate、pause、resume、archive | policy_read / policy_write |
| POST `/policies/{id}/previews` | 解析 Scope 并冻结计划预览 | plan_preview |
| POST `/policies/{id}/plans` | 校验前置条件并保存指定预览 | plan_save |
| GET `/plan-previews/{uuid}` | 候选任务状态、计数与计划摘要 | policy_read |
| GET/POST `/resources/{id}` | 读取版本目录；create、version、activate、deprecate、archive | resource_read / resource_write |
| GET/POST `/software-sources/{source}/candidates/{id}` | 读取；candidate、validate、approve、authorize、publish、recover、retry、withdraw | release_read；其余动作分别对应 release_write/validate/approve/publish/recover/withdraw |

Group create 提供 name、description、criteria；criteria=null 创建静态组。静态 members 提供 add/remove，不允许改动态成员。
规则 AST 与 Inventory 字段字典见[统一资产指南](202609210000-2463-unified-assets.md)。
预览、重算和静态成员更新异步返回 `202`、`task`、`statusUrl`。重算 input 为 `{"action":"recompute"}`，不再传 snapshot。
定义更新回执可附带自动计算任务。任务完成后分页读取不可变成员、差分与解释；预览不发布成员。
Snapshot/Delta、空 Snapshot、Manual Set/Null/Delete、注册及来源变化在原事务记录历史与 durable ingress，
RSS 负责 claim、lease、重试与恢复；Group 只有 Match 入组，合法 Unknown 不入组，不完整输入拒绝发布。

Scope put 的 definition 为 targets、limitations、exclusions；每项引用为 `{ "kind":"group|device", "id":"..." }`。
limitations=null 表示不限制，[] 表示空限制。最多 1000 个来源、1,000,000 个当前设备；1,000,001 拒绝发布，不静默截断。
来源分别绑定业务定义、已发布成员和注册身份版本；初始空组也有合法来源版本。无成员差分不推进 memberVersion。Scope 和组引用的变更/删除在同一受控事务中序列化。
被计划历史引用的 Scope 不能删除；被当前 Scope 或计划历史引用的组不能删除。设备撤销属于安全动作，不被 Scope 引用阻止；失效设备不能生成新有效目标。

Policy activate 指定 version、resource、resourceVersion，载荷摘要从被冻结/激活的真实资源版本解析。
预览 input 为 scope UUID 和 expectedRevision（与外层一致）；保存 input 为 preview UUID。
预览固定已发布 Scope、策略版本与引用令牌，异步准备目标和意图。每个策略只维护一个当前候选指针。
保存已完成候选使用短事务重新校验权限、Scope/Group/注册身份、策略 CAS 和引用令牌，
更新当前计划、最近保存 Scope 绑定、幂等回执和审计。过期候选返回 409，不偷偷重算。
保存只保存意图；前后执行事实数量不变，不创建 Planned、不批准执行、不派发命令。
实际执行受理及进度由独立 `RecordExecutions` 接口记录，不能依赖保存预造事实。
最近保存 Scope 后续变化只生成候选；绑定替换后旧 Scope 不再触发该策略。暂停/归档仍由 Policy 核心分类，自动产物不执行。

所有集合使用摘要与有界页，每页最多 1,000 对象和 16 MiB；解释还遵守规则访问与解释数量预算。
游标绑定租户、owner、结果身份和查询条件，每页重新授权。`nextCursor` 原样续读，尾页允许为空。

| GET 结果路径（`/api/v2`） | 内容 |
| --- | --- |
| `/groups/{group}/results/{result}/{members\|changes\|decisions}` | 成员、差分、规则解释 |
| `/scopes/{scope}/results/{result}/{members\|decisions}` | 目标成员与集合解释 |
| `/policies/{policy}/results/{result}/{targets\|add\|supersede\|retain\|cancel\|predecessors}` | 目标、意图及多版本替代关系 |

`dispatch=not_requested` 明确保存未派发。历史结果固定，不因后续事实或成员变化而改写；执行历史不受百万当前设备上限截断。
Resource version 输入包含 kind、不可变 version 和完整 variants。归档同时检查发布引用与 Policy 历史引用，不能由客户端声明零引用。

## 审批与外部提交

候选引用真实资源版本及 Submission；服务端验证完整 WinGet/Brew 内容和公开产物摘要。
审批动作指定 ring 和 publisherSubject（本产品已配置 release_publish 的主体）；审批人由当前可信会话确定。
审批/发布核心记录 `(client,subject)` 的规范身份，默认禁止同一管理主体审批并发布；DTO 中不存在可覆盖当前操作者的字段。
固定服务审批人/发布人已经移除，受控后台身份仅用于源执行和对账。旧服务账号审批不能为新的管理员身份提供发布授权。

每环 validate → approve → authorize 后，publish/recover 指定 ring、实际 publication 摘要数组和 attempt。
服务端在外部操作前保存原请求及固定时间的审计意图；外部提交成功、本地回执未知时按原 publication/attempt 对账，不生成另一份发布。
HTTP 返回当前候选视图，重放不会再次发起已确认提交。`published` 只表示已确认源元数据与批准内容一致，不表示客户端安装。

## 外审修复验证（PR 1023）

管理业务时间由宿主必填注入；每次新事务读取一次，Scope 来源与计划使用同一 Timepoint。两个池在生命周期中分别命名为 `management-runtime-postgres` 和 `software-driver-postgres`。

HTTP 拒绝保留管理 action、target、actor、client；publication HTTP 完成审计明确区分 success/replay/unknown，结果未确定返回 503，调用方保留原操作身份。preflight 仅证明接纳，其审计副本正常终结，不产生取消告警。

不存在的组、规则、Scope、Policy、资源、预览、设备、软件源、候选分别返回闭合的管理 404 code；不会使用 `inventory_not_found`。保存已生成预览时，其设备或 Scope 消失/失效属于 stale，返回 409。管理响应由应用层类型化 DTO 投影，不直接将 core/adapter 的序列化布局作为 HTTP 契约；WinGet manifest 是源协议拥有的文档，由对应源验证。

Scope 集合测试覆盖 target∩limitation−exclusion、解释、来源变化冲突与并发保存；HTTP 消费者覆盖 1001 目标分页和保存前后执行事实数量不变。百万静态/动态组、Scope、Policy 与超过百万条多版本执行历史由 `make capacity` 实际运行；证据和限制见 [#2464 设计](../architecture/202609221249-2464-asset-automation.md)。

撤回完成审计依据原事务的实际重放回执和源终态；未发布候选也区分首次撤回与同请求重放，新的操作身份不会仅因候选已隔离就被标为 replay。幂等回放同样在成功审计前验证响应投影，损坏的回执归 ManagementStorage，不写成功审计。


## #2463 当前资产接口

资产详情、字段、搜索、保存查询与 Group 类型化接线以 [统一资产指南](202609210000-2463-unified-assets.md) 为准。资产接口已一次性替换来源选择和旧字符串 DTO；来源在每个字段的证据中返回。采集运行诊断仍按其真实注册/来源关联。字段无有效期、TTL 或自动过期，旧部署需独立处理，安装器拒绝旧清单。
