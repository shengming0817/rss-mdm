# Group PostgreSQL（N09 / #2387，#2464 有界替换）

`rss-mdm-group-postgres` 持有组定义、不可变规则、成员版本、计算进度、解释和差分。
唯一规则语义由 [Group 核心](202609090000-2380-group-core.md) 持有；应用负责资产输入、权限、RSS claim 与引用组合。

## 公共调用

宿主将同一个 `Arc<PgRuntime>`、tenant 和有界 deadline 传入 `GroupStore::new` 并负责关闭。
`*_in` 校验 runtime/tenant，只借用事务，不自行 commit。必须将业务拒绝和 PG 失败交给外层事务处理。
组和操作 ID 为非 nil UUID；设备标识最多 256 UTF-8 字节，成员页最多 1000 项。

| 操作 | 结果与约束 |
| --- | --- |
| `execute(Create/Edit/SetRule)` | 定义及规则版本 CAS，不在事务内计算全量成员 |
| `execute_in(Delete)` | 宿主先检查引用，逻辑删除保留历史 |
| `begin_build_in` | 固定定义版本、输入版本、时间与原操作身份 |
| `append_build_page_in` | 同一规则求值有界动态输入页；页内容摘要和游标原子保存 |
| `advance_static_in` | 应用最多 1000 项的静态 add/remove；不复制已有全组成员 |
| `seal_build_in` | 完成输入枚举后封存计数 |
| `advance_difference_in` | 对固定新旧版本逐页计算差分和摘要 |
| `publish_build_in` | 再验前置条件、切换指针、写回执与摘要事件 |
| `affected_groups_in` | 输入最多 1000 个设备，按最新已发布静态成员反向查询，可包含动态组；组 ID 游标，输出最多 33 个组 |
| `build_in/current_member_set_in` | 恢复进度或获取当前不可变结果身份 |
| `build_members_in/build_changes_in/build_decisions_in` | 分页读取成员、差分与类型化解释 |

静态和动态组共用发布机制；当前容量为 1,000,000，超出明确拒绝。无成员差分不推进 memberVersion。
静态成员以修订差分保存；读取指定修订只合并已发布版本及本轮变化，后来的写入不改写历史结果。
完成事务不复制百万行，不跨页持锁。调度、claim、lease 和失败重试均由 RSS 持有。
提交未知保留原操作身份，读取原进度或精确重放；不能以新 ID 猜测旧事务是否提交。

## 存储与安装

外部 owner 按固定摘要顺序执行历史迁移、`0003_member_generations.sql` 和追加的 `0004_member_reverse_index.sql`，运行时只接受当前 schema。
旧 operations 文档、members/deltas 全量运行路径已删除，无旧快照解码、导入或双读。
规则采用唯一受校验编码；分批结果与原输入身份不可变。历史只允许按引用关系回收，没有字段 TTL。

启动验证精确 catalog、约束/索引、FORCE RLS、租户策略、runtime owner 及最低权限。
`catalog.json` 由正式 PostgreSQL 迁移提取后复核；CI 只检查，不自动接受漂移。
运行角色无 DDL、owner、BYPASSRLS 或转授权限，不得删除恢复历史。诊断只返回安全类别，不含资产值。

## 验证

`make t2-group` 覆盖公共独立消费、事务回滚/重放、提交未知、版本竞争、分页进度、历史读取与权限漂移。
`make capacity` 实际运行百万静态/动态成员、零/单设备/1%/全量变化及多一设备拒绝。
独立消费入口 `hack/group_postgres_consumer.py` 只在明确的消费者验收任务中手动运行，不属于本地 CI；
它从精确 Git SHA 构建，核验 normal/build 可达闭包、依赖身份和 feature，产物写入 `artifacts/group-postgres-consumers/`，不进入 CI result.json。
最终 `make ci CI_BASE=origin/develop` 绑定干净 HEAD。容量资源证据见 `artifacts/capacity/`；合成设备身份不代表真实终端 T3。

事务语义来源：固定 RSS revision `ec67bd142d70cb8f0d56feae636ac9471e7471fc` 的公开
transactional messaging / reconcile API，以及 SQLx v0.9.0 `sqlx-core/src/transaction.rs`。
Drop 只请求 rollback，不能证明已经回滚；沿 RSS LocalTxAttempt 处理不确定结果。
