# Group PostgreSQL（N09 / #2387）

`rss-mdm-group-postgres` 持有静态组定义/手工成员、动态规则版本、持久重算输入、运行结果与差分。
规则语义唯一由 [Group 核心](202609090000-2380-group-core.md) 持有；适配器只通过借用的
`Rule::view` / `Criteria::view` 编码，不增加公开规则 DSL，也不读取 Inventory 或系统业务时钟。
本包不发布到 registry；下述验证是固定 Git 源码消费和 T2，不代表产品 API 或真实设备 T3。

## 公共调用

宿主构造固定 RSS revision 的 `Arc<PgRuntime>` producer，并把同一个 runtime、tenant 和有界 deadline
传入 `GroupStore::new`。宿主持有 runtime 关闭职责。运行身份和 Group/Operation ID 均由调用方提供；
组和操作 ID 是非 nil UUID。`rss_mdm_group_postgres::core` 重导出同一个 Group 核心命名空间，
单包消费者可构造原始 Rule/Snapshot，不产生第二套规则类型。接口和共享可运行例子见 [rustdoc](../../crates/group-postgres/src/lib.rs)
及 [公共消费测试](../../crates/group-postgres/tests/consumer.rs)。

| 操作 | 结果与约束 |
| --- | --- |
| `execute(Create/Edit)` | 创建、修改元数据 |
| `execute_in(Delete)` | 在宿主事务中逻辑删除，清空现有成员但保留规则、运行及差分历史，ID 不复用 |
| `execute(Members)` | 仅静态组；批量 add/remove 排序去重，同一键同时增删拒绝 |
| `execute(SetRule)` | 仅动态组；同一组的规则版本与内容摘要不可变；旧版本重新使用仍检查原内容 |
| `rule(group, version)` | 获取不可变的当前或历史规则本体；当前版本取自 `get().rule_version`，未知或其他 tenant 返回 None，逻辑删除后仍可读历史 |
| `get/members/delta` | 读取组、现有成员、按对象键排序的有界差分页；逻辑删除仍可读取组元数据和历史差分 |
| `preview` | 同一核心求值；允许部分候选/coverage，不写运行、成员、版本或事件 |
| `start_recalculation` | 接收完整候选快照、固定 as_of、规则版本、基准组版本与 Manual/Periodic/Change 原因 |
| `recoverable/resume/get_run/result` | 按原操作 ID 发现、恢复及读取运行；历史结果读取持久决策和解释，不重新求值 |

`group_revision` 是唯一 CAS 序列：实际定义/成员变化，以及每个成功的新重算都推进一次。
`member_version` 是最后一次真实成员变化所在的 group_revision，初始空组为 0；无差分重算推进
group_revision 并完成回执，使同一旧基准的其它 Pending 运行失效，但不伪造成员变化事件。
事件版本允许空档，不是完整 CAS 日志；消费方不得通过事件数量重建当前 revision，写入应读取当前组并处理 VersionConflict。
完全相同的命令重放返回原回执；同一 operation ID 改变内容、as_of、基准或触发信息拒绝。
静态无效增删/相同元数据仍保存幂等回执，但不推进组版本。

运行仅有 `Pending → Completed | Rejected`。接收时冻结完整调用方输入，规则以不可变版本引用；
不复制旧成员。恢复先锁组、核对基准，再读取旧成员，出事务计算，提交前再次 CAS。
因此进程重启后不依赖调用方重新提供事实；规则修改、成员变化或删除使旧运行显式拒绝。
临时 SQL/连接失败、取消和提交结果未知保留 Pending 或实际已提交终态；不把不确定性标成业务失败。
`get_run` 返回固定触发信息、as_of、终态及接收至完成的数据库时间差（微秒），Rejected 提供封闭原因码；
宿主按原 operation ID 关联返回的安全 RSS 错误分类，负责重试策略和运维指标。
没有后台 worker、租约、自动重试或定时器。Periodic 的 slot 和 Change 的 source/event 仅是调用方证据，
不会额外建立第二个去重键；调度方必须稳定保存原 operation ID。

## 事务、事件与边界

所有有效写入与 `PgOutboxWriter` 在同一 RSS local_tx 中完成。消息 domain 为 `mdm-group`，route 为
`group.changed`，contract 为 `mdm.group.changed` v1，partition 为 group UUID，message ID 为
`group.changed.v1:{operation_id}`。payload 字段使用 camelCase（如 `groupId`、`groupRevision`），仅携带变化类别、组/操作 ID、版本及数量；
完整 added/removed 从 durable delta 查询。规则和事实不进入事件；schema 的精确文件字节摘要进入 RSS metadata。
事件属于 Group 业务变化通知，不代替 N12 成功审计。RSS runtime、schema/lineage/epoch 和安全错误分类复用固定公共实现。

`execute` 对 Delete（包括重放）返回 `CompanionTransactionRequired`，删除只能经 `execute_in`。
`execute_in/start_recalculation_in/lock_reference_target_in` 在任何读取、写入、幂等重放和无差分路径前，
都调用 RSS producer 的 `validate_transaction` 校验不可伪造的 runtime owner，再核对 tenant；不提交事务。
N12 必须先锁目标组，再检查/插入引用和执行删除，成功审计也在同一个外层 local_tx 中写入；
审计或引用 SQL 失败必须通过外层 `Err(PgError)` 回滚。处理 `InTransaction` 两层结果，不吞掉数据库错误，
宿主仍不得执行事务控制 SQL 或改变 tenant 设置；混用其它 runtime 会在入口被拒绝。多组操作先按 Group ID 排序加锁，之后再锁操作 ID。
本包只提供接缝，尚未实现应用级权限、引用 repository 或审计装配。

收到 `CommitUnknown` / `RollbackFailed` 时保留原身份，重新连接后查询/重放。
接收已提交的运行可直接 resume；接收尚未持久化且查询无记录时，调用方仍需原输入重放。
不能用新 ID 猜测执行，也不能把无确认回滚或连接关闭当作未提交的证明。

## 安装、数据与权限

由外部 migration owner 先安装固定 RSS messaging migration，再一次性应用
[0001_group.sql](../../crates/group-postgres/migrations/0001_group.sql)；应用运行路径无 DDL。
`mdm_group_runtime` 必须先创建。该角色仅有 Group schema USAGE，五表 SELECT/INSERT，members DELETE，
groups/operations 指定列 UPDATE；无 owner、superuser、BYPASSRLS、角色管理、建库、schema CREATE 或授予权限。
GroupStore 入场核对这些有效权限、FORCE RLS、精确 tenant policy，并拒绝 Group schema 中额外函数/非表索引 relation。
同时将 [catalog.sql](../../crates/group-postgres/src/catalog.sql) 的列类型/NULL/default、全部 PK/FK/CHECK 定义与验证状态、
全部索引定义/predicate/valid/ready/live 状态，与 [catalog.json](../../crates/group-postgres/src/catalog.json) 固定契约逐项比较。
该契约由本次 owner migration 在固定 PostgreSQL fixture 上提取后复核；CI 只校验，不自动接受或重写漂移结果。
修改 migration 或 PostgreSQL 版本时须重新复核并运行 mutation T2，不把探针当作完整生产数据库审计器。

存储故障通过 tracing target `rss_mdm_group_postgres::storage` 发出固定 `reason`：
`group.storage_contract`、`group.document_digest`、`group.stored_shape`、`group.row_count`、`group.outbox_identity`。
诊断不含 tenant、对象、规则、事实或原始 provider 错误；宿主配置 subscriber。
返回值仍保留 RSS 的安全错误分类和 Group 的独立事务结果，不能用诊断日志推断提交或回滚已确认。
RSS producer 所需权限见固定 RSS 迁移/运行角色契约；[T2 fixture](../../hack/group-t2.py) 展示最小独立角色组合。

五表全部 FORCE RLS，使用 RSS 事务设置的 `rss.tenant_id`，PK/FK 包含 tenant；无 tenant 会话不可读。
schema owner 负责可信迁移和备份完整性。运行角色不更新规则、原始请求或删除历史；应用只把 Pending
转入终态。没有数据库管理员攻击下的不可篡改承诺。

现有 Group 全部语义预算仍生效；静态命令 add/remove 原始列表在去重前共享 16 MiB 字节预算。适配器额外限制单个编码文档 64 MiB、规则版本 256 UTF-8 字节，
触发文档 16 KiB、名称/描述 4 KiB，描述不接受 PostgreSQL text 无法表示的 NUL。
对象 ID 保留核心的 4 KiB，使用 SHA-256 索引并核对原文，避免 PostgreSQL B-tree 单索引项限制。
快照保留事实原文，必须由宿主授权读取并按产品敏感数据政策管理备份、访问和保存期限。
本期逻辑删除保留全部历史，不提供 purge、TTL 或旧数据导入；后续清理须同时处理引用和恢复证据。
规则保持当前 V1 编码，事实快照和评估结果使用 V2 编码（无字段有效窗，含 Deleted/Conflict）：未知格式、摘要不一致或类型错误安全失败，无 legacy Go JSON/SQL/expr 转换或兼容双路径。

## 验证与来源

编辑循环运行 `cargo test --locked -p rss-mdm-group-postgres --lib` 和 `make t2-group`；
后者使用固定 digest PostgreSQL、verify-full TLS 和最小 producer 角色，强制实际执行完整测试名集合。
覆盖并发重放/冲突、规则与删除失效、无差分 CAS、事件先后失败回滚、跨 tenant、入场权限漂移、
4 KiB 对象键、子进程接收后强制终止，以及代理丢弃真实 COMMIT 响应后的原身份恢复。
故障矩阵和公共 consumer 均随包入库，未启动 relay/broker 或设备通道。

提交干净 HEAD 后 `make ci` 运行所有本地 gates，包括 `hack/group_postgres_consumer.py`。
该脚本从精确 Git SHA 创建 workspace 外 consumer，只直接消费这一个产品包，另显式声明公共签名和
fixture 所需的同 pin RSS/PG/异步支持包；公共用例覆盖静态 CRUD 和动态创建/预览/持久重算、重启后读取/更新/历史规则。检查这些包均属于 adapter 的 normal/build 可达闭包。
Cargo metadata 会保留 SQLx 未启用的弱可选驱动边；guard 限定其父边来源及缺失的启用 feature，
再用全目标 cargo tree 验证实际闭包不存在 MySQL/SQLite 或 HTTP 包，保留两份证据。
固定 RSS PG adapter 传递启用 tmsg core 的 consumer/default/producer，gate 校验这一实际集合；运行身份仍为 producer，未授予 inbox/relay 权限。
额外用仅一个 adapter 依赖的 baseline workspace 做 locked check，并对照 metadata 确保行为 consumer 未补齐任何依赖或 feature。
default/no-default 分别使用独立 Cargo 配置/home/lock/target，固定工具链，排除祖先 Cargo 配置和隐式 feature。
保存 metadata、feature tree、lock 摘要、实际命令、TLS PG 公共行为结果至
`artifacts/local-ci/group-postgres-consumers/`，总证据绑定源码 SHA 和 RSS revision。
本期没有远端 CI、性能容量/RPO/RTO 或产品 T3 结论。

事务生命周期参考 [SQLx 0.9 transaction.rs](https://github.com/transact-rs/sqlx/blob/v0.9.0/sqlx-core/src/transaction.rs)：
Drop 仅请求 rollback，不能推导已确认回滚；实际结果复用 RSS `LocalTxAttempt`。
RSS 固定 `ec67bd142d70cb8f0d56feae636ac9471e7471fc` 的
`crates/transactional-messaging-postgres/src/transaction.rs`、`outbox.rs` 为同事务与幂等事件消费来源，
精确依赖身份仍以 Cargo.toml/Cargo.lock 为准。

Catalog 校验参考 PostgreSQL 官方 [pg_constraint](https://www.postgresql.org/docs/17/catalog-pg-constraint.html) 与
[pg_index](https://www.postgresql.org/docs/17/catalog-pg-index.html)；wire 字段采用
[Serde rename_all](https://serde.rs/container-attrs.html) 统一投影，无旧字段别名。
