# 注册许可与审计操作

适用 #2347 的单实例管理员入口。静态权限变更需重启，Identity 每请求在线验证；已验证的在途请求沿用 #2343 边界，不承诺追溯取消。accepted 只代表申请受理，不能用它证明设备身份、发证或 Windows 注册成功。

## 升级和配置

先停止应用，用部署凭据预建 mdm_access 登录角色（NOSUPERUSER/NOBYPASSRLS、无成员继承），运行现有 mdm_owner migrate，再部署新配置和 binary。原 migration SQL 不修改；不完整安装按迁移诊断检查，不删除账本强行重试。新迁移需角色存在，缺角色明确失败。

服务配置必须新增 access_database，结构与 database 相同，host/port/name 必须一致，user 固定 mdm_access，password_file 使用独立 0600 文件。原 database 仍为 mdm_api。fixtures/mdm-config.example.json 是完整样例；旧配置缺字段直接拒绝，不存在只读降级启动。公开 application 构造入口新增 Arc<AccessStore> 参数，由调用者连接和关闭；生产 serve 统一拥有两池生命周期。

每条 binding 必须显式填写 allow_enrollment；false 拒绝注册管理，true 还必须同时拥有 super_admin 或 mdm_admin 和目标设备范围。其它角色配置 true 拒绝启动。没有角色、范围或显式许可均不授权；Identity 管理员不自动成为 MDM 管理员。

identity.client_id 最多 255 UTF-8 字节，超限在启动编译配置时拒绝，保证许可和审计持久化可接受该标识。

## 管理 API

使用已登录产品会话、精确 Origin、X-MDM-Request: 1、X-CSRF-Token 和 Content-Type: application/json。每次业务操作生成一个非 nil UUID Idempotency-Key 并保存，重试保持该键和业务参数不变。路径统一以 /api/v1 开头。

| POST 路径 | JSON | 结果 |
| --- | --- | --- |
| /enrollment-grants | {"device_id":"device-1"} | operation_id、grant_id、status=issued、expires_at、request_id=null |
| /registration-requests | {"device_id":"device-1","grant_id":"UUID"} | status=accepted、申请 request_id，消费一次许可 |
| /enrollment-grants/{id}/revoke | {"device_id":"device-1"} | status=revoked，无申请 |

成功 HTTP 200；身份无效 401、无权/错误归属/过期消费 403、输入错误 400、同键异请求或不可转换状态 409。依赖和审计故障 503；operation_unknown 表示提交未知。响应 x-request-id 用于请求诊断，Idempotency-Key 回显已解析操作身份；成功 body.request_id 是持久申请标识，两者含义不同。默认许可 300 秒且单次；grant_id 不能代替管理员登录。

超时、取消或 503 后重发同一操作键和请求。恢复成功返回原操作回执，不重新授权一个新许可、不续期；当前身份/权限失效时仍拒绝恢复。签发原回执不证明许可当前可用。不要通过生成另一操作键掩盖未知结果。

## 审计和故障

资产结果只有查询审计成功后才返回。许可签发/消费/撤销的成功审计和业务事实同事务；审计写失败回滚。拒绝、查询及重试分别保存 denied/failed/success/replay，提交不确定记录 unknown。审计包含可信 tenant/actor/client、目标、操作和请求关联，不包含凭据明文；未知主体不从输入猜测身份。

audit_failure 是结构化 error 级运维告警，包含 request_id、已知 operation_id、闭合 action、write_outcome 和原因；不输出 actor/client/target。收尾审计不可用只发一条 persistent_audit_unavailable；事务审计失败且收尾成功时发 transaction_audit_failed。部署 owner 应将该事件接入现有日志告警，按请求所属租户和 request_id 定位、恢复 PG/权限后以原操作键核查；不可将日志行作为持久业务审计。追加迁移 access-audit-request-index-v1 提供 (tenant_id,request_id) 索引，保留已有迁移摘要。应用不自动清理审计；保留、授权取证和备份由部署 owner 管理。缺少告警采集不影响应用拒绝行为，但不能声称已完成生产告警接入。

## 验证

编辑循环运行 cargo test --locked -p rss-mdm-app --lib；make t2 使用一次性真实 TLS PG 和正式迁移；MDM_IDENTITY_CANDIDATE 指向 fixtures/identity-candidate.json 精确匹配目录后运行 make t2-identity。最终提交受测源码后运行 make ci；临时日志位于 artifacts，不充当唯一验收记录，PR 保存 HEAD、固定候选、命令和结果。未验证设备 T3。

运行角色对 grants/operations 仅有必要 SELECT/INSERT，对 requests/audit 仅 INSERT，另允许 grants.state UPDATE；审计查询由部署 owner 单独授权，业务运行凭据不能枚举审计历史。
