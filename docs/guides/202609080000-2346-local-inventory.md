# F01 本地 Inventory 组合

本项由 Inventory 核心、PostgreSQL 适配、fixture 示例与独立 T2 包组成，消费固定 RSS Git revision；仅建立本地 CI。
它验证产品基础 T1/T2，不提供设备认证、CollectionRun、管理 HTTP API、跨来源合并或真机 T3。

## 依赖与构建

根目录 `Cargo.toml` 的 `[workspace.dependencies]` 中所有 RSS 公共依赖固定同一 Azure Git URL 与完整 `rev`；版本和上游闭包由
`Cargo.lock` 锁定。没有 path patch、候选制品解包目录或 registry 备用路径。
各 crate manifest 继承共享依赖、包元数据与 lint。资产规则由 `crates/inventory` 持有；
投影、schema 与权限检查由 `crates/inventory-postgres` 持有；fixture 授权和运行装配归 `crates/examples`。
产品 SQL 在 `crates/inventory-postgres/migrations/`，迁移执行由示例组合根负责。
下列命令均从仓库根目录执行。配置系统 Git 的 Azure 只读 credential helper 后运行 `cargo build --locked`。
不要把 token 写入 URL、manifest、lock 或日志。缺 revision/鉴权失败必须解决，不能回到父仓源码。

需要 Rust 1.96.0、系统 Git、Python ≥3.11、OpenSSL 与 Docker。运行 `make test` 做全部成员 T1 测试，
`make t2` 启动固定摘要的 PostgreSQL 16 TLS 临时容器，测试后删除。
`make ci` 是唯一完整本地入口：先提交受测源码，再运行。它运行全部 gates 后汇总失败，
同时从受测 HEAD 创建 RSS 目录之外的干净 checkout，用全新 Cargo home/target 验证普通及
integration feature 组合。网络需可访问 Azure 和 crates.io；不设置完整 CI 总超时。

日志、metadata/tree 和绑定 HEAD/lock 摘要的结果保存于 `artifacts/local-ci/`（忽略目录）。
本地 CI 不注册 Azure pipeline、GitHub workflow、runner 或远端构建策略。

## 安装与运行

数据库必须独立用于此组合。管理员先创建 `mdm_owner` 和 `mdm_runtime` 登录角色，均为
`NOSUPERUSER NOBYPASSRLS`；按安全方式单独设置密码。向 owner 授予目标数据库 CREATE 和
public schema CREATE。runtime 不可通过角色继承/SET ROLE 获得 owner 或特权角色权限。启动时校验产品 Inventory 的强制 RLS、精确租户策略、唯一键和运行/PUBLIC 权限；配置漂移会拒绝接收工作。

所有连接强制 `VerifyFull`；设置 `PG_CA_FILE` 为可信 CA PEM 路径。
通过安全环境配置 `DATABASE_URL` 为 owner 后运行：

```sh
cargo run --locked -p rss-mdm-examples -- migrate
```

迁移记录保存组件 SQL 摘要和完成状态；同一迁移重复执行验证身份后跳过。
组件迁移自身拥有事务边界，因此跨组件安装不是一个事务。中断/摘要变化会阻断重跑；
本项仅支持新库安装，失败后恢复安装前备份或重建专属测试库，不自动修补半安装状态。
不得删除迁移记录后强行接纳未知 schema。

切换 `DATABASE_URL` 为 runtime，并设置 `MDM_SCOPE_FILE=fixtures/scope.json` 后：

```sh
cargo run --locked -p rss-mdm-examples -- ingest-fixture fixtures/snapshot.json
cargo run --locked -p rss-mdm-examples -- project
cargo run --locked -p rss-mdm-examples -- inspect snapshot-1
```

scope 文件由本地受信操作员提供，不能由未认证客户端提交；报告文件没有 tenant/权限字段。
fixture 的 `observedAt` 是固定样本时间，新增报告应使用实际采集秒数和稳定 batch/sequence。
相同 batch 的重传不得修改时间、内容或身份；不同内容将冲突。

## 两阶段事实与恢复

`ingest-fixture` 返回 durable receipt 仅表示接收完成，Inventory 状态明确为未确认。
`inspect` 返回原 receipt、该 batch 的 `projection`（`projected` / `not_projected`）、租户 journal 的
checkpoint 与指定完整流的当前资产。`projected` 来自固定 RSS revision 的 PgSource v1 event identity
（完整流 batch fingerprint 的小写十六进制）对应的持久投影 receipt，按租户、journal、projection 与
generation 限定；空 Snapshot、删除最后字段与 commit-unknown 后重启均可确认。
`not_projected` 表示尚无该持久事实，也适用于未接收或不进入 journal 的 Partial/Failed；结合原 receipt
区分原因。checkpoint 仅表示租户 journal 进度，资产是当前值，均不替代逐 batch 证明或设备健康状态。

完整 Snapshot 只替换同 tenant/journal/generation/完整 scope/coverage 的字段；Partial/Failed
保留原 receipt、要求新快照但不进入资产投影。Delta 仅执行连续基线上的显式更新/删除。
当前 coverage 固定为 device-basics/1/model-os/utf8-v1，字段仅有 device.model 和 device.os.version。
每个值是 1–256 字节无控制字符 UTF-8 文本。非 Inventory dataset 被有意过滤；目标 dataset
的未知格式/字段/coverage 会阻断投影，不能跳过后推进 checkpoint。

`project` 捕获调用开始时的 journal 水位，从持久 checkpoint 接管并分批处理到该水位。并发新增记录留待下一次调用；持久 generation 保持 live，不冻结为首次水位。没有后台无限重试。
报错或 commit unknown 后先 `inspect`，再以相同身份重新接收/运行 `project`；已提交则去重，
未提交则重放。不要据一次查询未找到 receipt 推断在途提交必定回滚。

Observation/Projection 各自接管独立 pool。组合根拥有关闭责任；Ctrl-C 先取消并有界等待操作，
再用独立排空预算关闭两个 store。每次预算转换为当前时钟坐标下的新 deadline；操作与关闭同时失败时保留全部脱敏阶段诊断。超时明确失败；进程终止由 PostgreSQL 连接/事务恢复兜底，
不能把取消或关闭超时当成外部事实回滚。

## 证据与限制

T2 在最低运行角色下验证资产/进度同回滚、接收已提交后恢复、重传与冲突、多租户隔离、
完整/部分报告、worker 重启、进程终止、ACK 丢失以及关闭路径。
PG 不可达、错误凭据或证书是失败，不是 skip；源码测试不能替代本产品 T2。
实际运行结果以 PR 绑定的本地 CI HEAD 与 artifact 为准。不宣称 registry/candidate 发布、远端 CI、
Windows/macOS 真机、生产迁移或端到端认证完成。

参考：RSS observation-postgres/examples/handoff 与 projection 公共接口（固定 manifest revision）；
[SQLx v0.9.0 pool 源码](https://github.com/launchbadge/sqlx/blob/v0.9.0/sqlx-core/src/pool/mod.rs)。

示例 `App::open` 必填共享 `Clock`；CLI 显式选取真实单调时间，Observation、Projection 和每次调用的
Deadline 由同一源派生。示例 raw stores 私有；examples 的 `integration` 仅开放完整 T2 场景入口，
由 `tests/inventory-postgres-integration` 调用，不返回组件或事务句柄，普通 feature 图不编译故障场景。
PostgreSQL adapter 公开 `Inventory<C>` 投影 effect、定义身份、迁移 SQL 和权限检查，供产品装配消费；内部 source 私有。Ctrl-C 监听成功报告 `cancelled`，监听失败
报告 `signal / runtime / SignalUnavailable`；两者都执行有界排空与清理，provider 文本不进入 JSON。

本仓 `Cargo.toml` 与 `clippy.toml` 共同拥有时间源 lint；真实时钟例外仅在组合根/测试项上注明原因。
隔离 checkout 在普通与 integration 两种图执行相同 Clippy。CI 从 workspace 共享依赖及 member 的普通、开发、构建和
条件依赖解析唯一 RSS git/rev，并校验继承来源，再核对 locked metadata 并生成证据；脚本不维护第二份 pin。
