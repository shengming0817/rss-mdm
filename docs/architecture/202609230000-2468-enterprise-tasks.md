# #2468 企业脚本、采集模板与可靠任务调度

关联产品 PRD 的企业任务与扩展采集能力；owner 为 rss-mdm。此文记录已复核的实施设计，验收状态以测试与交付记录为准，不声明设计能力已经交付。

## 设计约束

- Resource.Script 是脚本及采集模板的唯一不可变版本 owner。采集模板使用 collection purpose 与字段映射，不建立另一套 CRUD/version。制品、平台、解释器、身份、参数绑定、输入/输出 Schema、预算及用途全部进入摘要。
- 脚本为 ActionRun；与期望状态命令共用 commands 的 PgRuntime、outbox、reconcile 与恢复装配。退出码零只表明进程成功，不能生成 StateDigest 或 Applied。
- Agent wire 升至 2.0.0，仅保留 `/api/agent/v2` 与 V2 schema。旧凭据不进入 V2，重新授权注册产生新 generation。资源管理改用 `/api/v3/resources/{id}`，其余管理入口不变。
- 参数只以字面量 argv 或 `RSS_PARAM_` 环境变量传入。JSON Schema 使用成熟验证器；禁止外部引用、方言切换与正则 Schema。平台和执行身份明确，不降级回退。
- 手动与计划任务共用原子 intake：任务、回执、审计及 outbox 同事务。审批者与作者分离，冻结版本、参数、目标快照、预算和有效期；生产、领取、启动和下载均重新校验当前权限及 registration generation。
- 投递、接收、启动许可、执行、取消及效果分别记录。启动后的副作用结果不确定时不得自动重执行。
- 调度支持一次、间隔、IANA 时区每周窗口及注册/签到；默认跳过错过的触发，可选择合并一次。DST gap 跳过、fold 取较早一次；窗口外保留同一 occurrence 等待窗口或截止；抖动确定性、签到有最小间隔。持久 occurrence 唯一键包含租户、计划版本、触发坐标和设备。
- 本地不可变制品在精确长度和 SHA-256 校验后原子落盘。task/attempt 本身是下载授权，不另建 grant；单段 Range、摘要 ETag、每次重新鉴权。ring Ed25519 签署任务和内容描述，缺少可信签名配置时拒绝执行。
- 扩展采集仅包含 `custom.corporate_agent.version`、`custom.corporate_agent.healthy`、`custom.osquery.version`。有限 osquery profile 只执行 `SELECT version FROM osquery_info;`。结果走 Observation → Inventory → query/Group；失败、截断、部分与非法输出只更新质量，保留 lastKnown，不引入 TTL。
- 实际 OS runner 属于 #2475/#2476，通信消费者属于 #2474。本任务不新建 RSS 通用 crate、独立 cron 平台或动态字段注册平台。

## 实施 DAG 与验证

主实施者串行拥有改动，同一文件不并行修改：

1. A：resource 定义/摘要 → resource-postgres codec → management DTO；agent-wire V2 类型/schema → Agent HTTP/认证 → current-contract gate。先验证非法参数、平台、摘要变化与 V1 拒绝的失败测试。
2. B：commands/ActionRun 模型 → 审批和权限 → 持久 intake/outbox → claim/ack/start/cancel/result 与恢复。覆盖并发幂等、commit unknown、审计回滚、撤权及旧 generation。
3. C：调度模型和持久 occurrence → 同一 intake；制品存储、签名和 Range 下载。覆盖 DST、错过触发、窗口等待、重启及跨租户/版本越权。
4. D：有限采集字段和 source → Observation/Inventory 投影 → 查询/分组；追加迁移、catalog 与 exact-baseline admission。覆盖不可信输出不覆盖已知值。
5. E：新增 `make t2-tasks` 复用 TLS PostgreSQL/Identity/HTTP fixtures；现有命令与资产回归；文档、固定 Git 与同一 `.crate` 的独立 Agent wire 消费；提交后一次产品本地 CI，按 ship 完成 PR、首审、修复及监控交接。

## 升级边界

只接受空库、a83f7876289f15f294940964df69579d62126557 的完整 39 单元 name+digest ledger，或当前完整 ledger。不得泛化为任意历史前缀升级。历史 SQL 不改写，新增 SQL 追加。升级前先排空待处理 Agent report 并撤销旧 Agent registration/credential；不带完整执行接口的旧 Script 版本拒绝升级，不推断默认值或删除。历史证据保留，但没有旧 wire 的运行时解码路径。Software/Configuration 的持久化及摘要不变。

## 实施复核补充

- 每份计划不可变，revision 固定为 1；修改需创建并审批新计划，停用旧计划。目标快照持有 device 集合，每次生产冻结当时的 registration/generation。
- 三项扩展字段各用固定 dataset、coverage 及注册内独立 Observation object，避免 object 级生命周期 CAS 冲突，以及多个模板快照互相删除字段。Agent 基础采集保留原两槽编码。
- Inventory 投影切换到 inventory-v3，从同一 journal 重放；旧事实及历史表保留。无效结果只产生失败采集证据，不重写事实或 lastKnown 的来源时间。
- 签名域包括 keyId，payload 包括平台/架构；消费者必须用本地可信 tenant/device/registration/generation/platform/architecture/task/attempt/permit 验签。
- 运行恢复使用持久分页游标。定时 occurrence 先确定不可变坐标，各设备加入抖动/窗口后分别判断 misfire；窗口延后不改变坐标。

## 内置审查后的计划修订

- 保持单一归档入口，删除 SoftwarePublication 未使用的通用 archive API；不新增兼容包装。
- 容量阻塞是可重试生产结果，不推进扫描坐标；手动审批在容量不足时整笔回滚。窗口结束进入既有持久 run deadline。
- Offer 候选与取消页分离；每 registration 仅保存一个取消游标，空轮询不写永久幂等回执，实际 offer 继续保留重放身份。
- 迟到结果仍保留执行证据，但 timeout/deadline/取消后的输出不发布可信事实。
- 计划元数据、20 条 run 摘要分页与单 run 完整证据分开读取；补齐 plan/task 审计关联。
- 固定 Git/打包 consumer 覆盖非空签名 offer、Start permit 和结果；真实 PG 恢复测试直接驱动生产 recovery funnel。
- F2/F3/F16 的 Cx3 处置已由用户经飞书批量确认，全部在当前 PR 修复，不 defer。
