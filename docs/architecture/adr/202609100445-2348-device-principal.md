# 通道中立注册主体与报告授权

静态 MDM 角色、binding 与 allow_* 授权部分已由 [#2363](202609200002-2363-persistent-authorization.md) 替代；下文相关段落保留为历史决策。
状态：已决定；#2348 实现与验证状态以产品 PR 的受测 HEAD 为准。

Device 是 tenant 内稳定的产品键，序列号等资产字段不是身份。agent/mdm 各有独立 Registration 世代；同一通道重注册保留 Device、替换世代，另一通道不变。单世代只绑定一个凭据、一个实际 V1 来源。凭据 locator 是可信 verifier 产生的规范摘要，同 tenant/channel 内终身唯一，不能复活或转绑；epoch 独立于 generation，每次注册新建。

管理员验证按 #2437 直接调用内嵌组件权威接口，取得请求级 AuthenticatedSession；注册凭据引用每次重新验证，不保存成功证明。绑定同时需要当前管理员的 MDM enrollment 权限、本人 F02 request、可信通道 proof、原操作键和预期世代。持久 request 不继承已消费许可的期限，但不能独自充当注册授权；当前权限消失时首次绑定和结果恢复都拒绝。事务以操作锁、申请锁、设备通道锁依次串行，预期世代冲突返回 Conflict。首次通道的预期世代为 0，已撤销通道也保留历史世代计数。

AccessStore 仍独占产品注册事务和最低 mdm_access 连接池。业务记录、回执、成功审计一次提交，绑定和撤销复用 F02 的恢复/提交接缝。未知提交只重试原键；恢复返回原结果，不保证凭据现在仍有效，更不重新激活旧世代。audit 中的 registration_id 可描述未提交的尝试，不以外键要求失败事实对应一条已提交注册。凭据摘要不进入审计或回执，操作摘要不保存原文。

手工撤销使用独立 allow_manage_credentials，加上 super_admin/mdm_admin 和设备范围；allow_enrollment 不继承它。撤销 registration、credential 和来源授权同事务。配置字段必填，调用方统一切换，不提供缺字段回退。

DeviceService 是产品 app 的 gateway 接缝。VerifiedChannelCredential 与 DevicePrincipal 无 public 构造和 Deserialize；I01 生产代码不能创建通道 proof，F04 在同产品 gateway 完成实际证书验证后才能接入。I01 不增加假的 verifier、占位认证端点或共享 Agent wire。可见 Rust 类型供产品接缝和边界验证使用，不意味着已经具备外部设备入口。

RSS 当前 object 拥有整个注册生命周期，不能直接等同统一 Device，否则双通道注册会互相退休。产品以 Registration UUID 作为 Observation object/registration，独立 source/epoch 作为流坐标；稳定 Device 由产品映射关联，管理响应使用该 Device。每个注册主体仅首次激活或精确重放，不能通过重试切换成另一主体。不另建 lifecycle revision 协调器，不修改 RSS fencing。

报告操作先复查持久注册、凭据和精确来源授权，再将无 I/O 的同步 Authority 接到 RSS。Scope 的 tenant/Device/registration/source/dataset/epoch 全部由服务器派生，coverage 固定现有 Inventory 契约。报告身份直接使用 RSS 的 (Scope,batch_id) 及规范指纹，sequence 只在同 Scope 排序，时间戳不决定跨来源胜者。产品 CollectionRun 判断两个字段是否完整并选择报告种类，RSS 持有 Snapshot/Partial/Failed/Delta 的状态转移与可应用性。

#2352/#2353 将报告准入线性化点改为 CollectionRun 事务：接受片段时再次按 registration、credential、source 顺序检查并锁定当前映射，协议响应、接受的内容与审计原子提交。正文接收最多 8 秒，组件认证和协议存储操作各按自身有界预算结算，额外最多 2 秒产品审计；旧 DeviceService::ingest 直接写入路径删除。

已接受字段在超时、取代或吊销时可以终结；不接受新的设备输入。封存的 Scope、batch ID、sequence、规范字节、指纹及接收时间不可变，它们构成跨进程的持久恢复授权，明确不受原 8 秒请求期限限制。恢复仅能递交这一份原报告到这一份原 Scope，后续重注册或吊销不能把它移到新世代。这不保留任意旧凭据或任意新报告的授权。

CollectionRun、Observation receipt 与 Inventory 投影分别拥有事务，不能声称三者原子提交。工作任务沿用原 batch 重试，RSS 独占其取消、提交未知、冲突及 readback 语义；lookup None 不是回滚证明。CollectionRun 只保存最小交付进度，receipt/checkpoint 的权威状态只从 RSS 读取。

journal 与设备报告权限分离。管理 HTTP 装配没有 journal 权限；产品宿主显式选择 worker tenant，取消并等待有界 invocation 后撤销其执行资格。每次启动工作任务取得绑定取消令牌的 journal grant，不从报告推导，不新增 journal 授权数据库或通用服务身份平台。

当前 Inventory API 只接受封闭 source，由服务器派生 channel；旧 channel 与 registration/epoch/tenant 参数全部拒绝。管理员资源权限检查后，服务读取有效映射并按精确 Scope+coverage 查询。映射读取是查询快照点，之后并发换代不追溯取消该请求。不同来源逐份返回，响应保留完整 lineage。旧 receipt/journal/Inventory 保留历史但不能经当前映射选中；既有 fixture 数据也不自动取得可信身份。

验证复用 make t2 的真实 TLS PG、正式迁移和最低运行角色。I01 保留绑定、权限、换代与撤销测试；报告恢复与投影由新的生产 CollectionRun/InventoryRuntime T2 覆盖。通道 proof 的模型用例仍是测试 fixture；真实 mTLS 由 Windows T2 验证，管理员认证使用自有 PG 中的真实组件凭据，MDM OCI 候选另验实际 HTTPS 登录和产品授权。F01 CLI 只保留自己的底层 fixture 验证，生产 app 不依赖 examples。T3 独立验收。
