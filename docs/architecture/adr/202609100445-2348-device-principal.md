# 通道中立注册主体与报告授权

决定：Device 是租户内稳定业务身份，Registration 持有独立通道世代，资产字段不作为认证身份。静态角色配置已由 [持久授权 ADR](202609200002-2363-persistent-authorization.md) 替代；#2352/#2353 将报告准入线性化点收敛到 CollectionRun 事务。当前行为见 [注册指南](../../guides/device-enrollment.md)。

## 身份与世代

Agent/MDM 的注册世代独立，重注册替换当前通道而不清空 Device 或另一通道。凭据 locator 来自可信验证器，不能复活或转绑；epoch 独立于 generation。绑定需要当前管理员权限、原请求、可信通道 proof 与预期世代，持久 request 自身不构成授权。

device 拥有绑定、凭据与来源状态；宿主注册生命周期协调者在同一事务中调用 device、协议及 collection 接口，operations 与 audit 结算回执和成功审计；恢复只返回历史事实，不重新激活旧凭据。审计允许记录未提交的注册尝试，不通过外键强迫失败事实对应成功注册。

## 报告与恢复

RSS Observation object 拥有来源生命周期，直接使用稳定 Device 会让双通道注册互相退休。因此注册和来源/epoch 组成流坐标，由产品映射关联 Device；请求不能自报 scope 权威，时间戳也不能决定跨来源胜者。

接受协议片段时锁定并复查当前注册、凭据与来源，内容、响应和审计原子提交。封存报告的 scope、batch、sequence、规范内容与指纹成为精确持久恢复授权，后续撤销仍允许递交这一份原报告；不能据此接收旧凭据的新报告或移入新世代。

CollectionRun、Observation receipt 与 Inventory 投影分别持有事务，不能宣称三者原子完成。工作任务重试原 batch，lookup None 不是回滚证明。宿主显式授予 worker journal 读取权，与设备报告授权分开；CollectionRun 不复制组件 checkpoint 状态。

资产查询按当前有效注册/来源解析历史，来源冲突与最后已知值保留证据；Manual 归稳定 Device。选择当前资产不会删除旧 receipt/journal，也不会给本地 fixture 赋予设备身份。具体来源算法归 Inventory，应用不另存一份规则。

## 独立 Device Access 身份

DevicePrincipal 的注册种类独立于 Inventory Channel：Agent 与原生 MDM 持有对应 channel，DA 的 `da_device` 注册没有 channel、report source、runtime binding 或必需的 MDM 关联。私有主体绑定安装实例、租户、device、registration、generation、credential 和用途；凭证只能由实际 TLS 证明经共享证书校验、当前数据库映射和原事务复验获得。DA 证书 SAN 另外绑定稳定安装实例，配置签名不授予设备身份。

Agent 与 DA 共用注册签发、未知结果恢复、候选激活和凭据替代流程；共享 PKI V1 Purpose 直接增加 `da_device`，旧 schema 直接替换，具体既有 Agent trust 内容的摘要不因 schema 指纹变化而变化。证书主体、SAN、provisioner 和用途均分别校验。

签名 owner 区分 `agent_task` 与 `da_configuration`，分别持有私钥、版本、ACK、操作回执及保护域。当前消费者从注册、有效凭据和 source 状态派生，不维护可独立编辑的成员表。两种用途均滚动激活，设备签发资格仍要求精确 ACK；旧进程和未 ACK 设备不能获得新签名。任务、telemetry 与 DA 导出在原事务登记各自的待验证窗口，退役同时检查这些引用和当前消费者的 verify-only ACK。

`device-access-http` 提供 `/api/v1/da` 生产入口与共享信任校验的 TLS listener，直接消费 Identity、授权、Audit、Registration、PKI 和 Task Trust。TLS 只负责真实证书验证，连接从接受到关闭的容量、准备/首请求/HTTP 头读取期限和停机排空复用固定版本 `rss-axum` 的 managed registration；宿主显式提供已验证的 `Http1ServePolicy` 并纳入 `rss-runtime` 生命周期。DA 内层以不透明 payload 签名已发布 Policy 的 AccessConfiguration、实例、租户、Policy/version/revision、独立 trustRevision、导出 operationId、接收范围、允许投递方式、原生预期与有效期；原始 payload 字节不可重新序列化；最大有效期由部署显式提供。管理员导出与设备领取分别授权，原始签名回执持久保存。内层配置签名、设备身份证书和外层 CMS 的钥匙与用途互不替代。
