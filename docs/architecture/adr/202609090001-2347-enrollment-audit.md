# 管理员注册许可与持久审计

决定：注册受理、幂等回执与成功审计由同一产品事务 owner 持有；只拿到目标设备 ID 不足以证明设备身份。静态角色与 allow_* 配置部分已由 [持久授权 ADR](202609200002-2363-persistent-authorization.md) 替代，认证按 [内嵌 Identity ADR](202609091750-2343-identity-authorization.md) 修订。当前操作见 [注册指南](../../guides/device-enrollment.md)。

## 原因与约束

注册是不可逆外部身份建立流程的前置授权，成功业务没有审计、超时换键重复受理、或把历史回执当当前权限都会造成权限与事实失配。因此许可、请求与回执各保留自己的含义，重放仍检查当前身份及资源权限；成功回执不承诺许可或凭据现在仍有效。

未知提交仅沿原操作与参数查询、精确重放，不因暂时查不到而断言回滚。签发意图先保存，绑定与成功审计最终原子提交；设备通道持有真实 proof，产品不引入占位 verifier 或通用幂等框架。

产品业务、查询和拒绝各按实际事务结果形成审计；组件认证仍持有自己的安全事件，产品审计不能覆盖已提交的组件响应。审计失败不放行数据或变更。取消时无法完成持久审计以闭合运维事件暴露，日志不冒充业务审计。

审计不保存凭据、token、请求正文或任意 provider 错误；运行角色不能更新/删除审计。保留和备份由部署 owner 管理，不宣称防 DBA 篡改或 WORM。

来源：[SQLx transaction.rs](https://github.com/launchbadge/sqlx/blob/v0.9.0/sqlx-core/src/transaction.rs)、[PostgreSQL 行锁](https://www.postgresql.org/docs/17/explicit-locking.html#LOCKING-ROWS)。
