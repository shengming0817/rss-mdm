# 验证范围

T1 提供模型与边界证据；T2 使用真实依赖提供持久化、权限、协议与恢复证据；T3 在独立产品任务中验证真实设备与支持矩阵。缺依赖或未运行不能宣布通过。

## 测试设计

通用约束强度、最低充分证明、唯一 owner 与迁移期载体退出遵循 [RSS AI-robust 规则](https://dev.azure.com/shengming0923/rss/_git/rss?path=/docs/rules/ai-robust.md&version=GBdevelop)。以下只规定 MDM 测试如何应用这些原则；文档要求不等于实现或验证已完成。

设计或调整测试时，按以下顺序确定：

1. **风险与动作**：说明当前可复发风险、实际消费者或明确外部承诺，以及本次真正要验证的动作；新增或保留测试须说明既有证明为何不足。
2. **层级与 owner**：纯模型、codec、真值表、算术边界归 T1；真实 SQL、权限、事务、传输、协议和恢复接缝归 T2；真实设备效果与支持矩阵归 T3。公共契约由所属 owner 的最小充分集合证明，消费者只补独有接缝，不复制公共矩阵。
3. **最小合法前置**：普通业务从满足实际消费者不变量的预置状态开始，优先复用兼容 baseline、批量 SQL 或现有最小种子。仅当注册、初始化、签发、发布流程或其必要接缝本身被测时，才走相应完整生产入口。准备不得 mock 掉被测事务、RLS、认证或签名验证，也不新增第二套迁移引擎。
4. **隔离与依赖**：按实际读写和观察范围选择对象、主体、租户或实例隔离；租户、账号、设备和证书数量由场景决定。稳定材料按兼容环境复用，会话按有效期需要签发；可变权限、轮换和故障保持必要隔离。正常 fixture 提供正常可用状态，恢复、冷备提升和异常材料由专项显式触发。
5. **断言与反例**：验证必需结果存在、目标状态或错误及必要副作用，避免空集合、无调用或始终失败也通过。对核心代表场景或已发现漏洞用最小反例核实断言能拒绝错误，不引入全量 mutation 平台，不以测试数量或通过次数代表覆盖。
6. **影响与退出**：按真实消费接缝选验证范围，准备依赖不递归展开为前置创建流程的全量验收。已有充分证明则合并或删除重复用例，不机械迁成等量 T1。职责迁移验证后继证明；需求退出记录依据并清理登记。历史兼容须有已接受的升级或消费依据，测试与指南互相引用不构成承诺。迁移期源码外形检查在稳定类型、依赖或行为证明接管后退出。

操作示例和现有执行器边界见[测试模块](../guides/test-modules.md#从被测动作选择前置)。

## 执行与证据

`make ci CI_BASE=origin/develop` 按影响范围运行快速检查，任何模式均不启动 PostgreSQL、网关或 IdP，不隐式执行 T2。`make t2 MODULE=affected CI_BASE=origin/develop` 运行受影响测试模块（裸 `make t2` 默认 affected），`MODULE=planning.http` 等选择专项，`MODULE=all` 选择全部；旧 SUITE/--suite 明确拒绝。执行与发现使用 `hack/t2_registry.py` 的唯一描述，affected 由 `hack/ci_impact.py` 统一选择，Rust 测试函数通过 nextest 实际发现。`make ci-full` 在同一构建租约内组合全部快速检查和全部 T2，正式候选和浏览器 T3 独立。本仓结果不由父仓 CI 代替；不新增远端 CI。

CI 直接验证当前工作区，不要求预先提交、clean HEAD 或冷构建。`make ci-plan` 仅预览；选择器比较基线 merge-base 与当前修改，计入未跟踪且非忽略的输入。docs/root Markdown 不贡献 Rust package seed，crate README 可参与 rustdoc。selection 分别记录 Cargo 的 `cargo.mode/packages` 与 T2 的 `t2.mode/modules`，并以原因区分业务影响、工具验证、代表场景与显式全量。Cargo 沿 normal/build 生产依赖传播，dev 边选中测试消费者后停止；独立测试及 helper 只选择所属包和直接验证，不继续向下游包传播；独立 T1 文件不选 T2，独立 T2 文件只选所属模块，helper 实现只选实际消费者，纯模块导出入口只编译和发现，不因共享 fixture 扩大业务执行。生产输入按模块声明的实际消费接缝选择，多个输入取并集。manifest/lock 仅决定 Cargo 检查范围，不自动选择业务 T2；依赖升级的必要运行验证通过现有 `MODULE` 显式执行，广泛组合由定期全量承接。日常业务 T2 按改动输入直接匹配一次，选中后不继续传播。登记、模块输入和可识别 rename/copy 合并基线与当前归属；职责迁移须指向当前后继证明；需求退出须说明退出依据并清理登记，不要求制造替代测试。模块删除由两版登记及实际测试载体推导，不保留旧名称或退出名册。幸存测试文件须由当前 T2/T1 owner 承接；受删除或 selector/build 变化影响的现存 target 在正式 CI 中仅编译/发现，拒绝无 owner 的 ignored 测试，即使业务 T2 选择为空也不跳过。退出的业务依据留 issue/PR；工具只证明登记与载体一致。未知输入、基线不可用、分析异常和非法结果明确失败，不执行隐式全量。存在脏文件本身不扩大选择。CI 在选择前与执行后核对当前文件集合、内容及状态，运行期间输入变化则失败，避免将旧测试结果用于新源码。

PG T2 提供持久化、SQL、权限与事务证据；协议 T2 提供真实 HTTP/TLS、身份、回执与恢复证据。App 反向依赖闭包不能直接代替 T2 路径映射。功能预算边界使用小输入或算术边界；规模与性能承诺由有明确场景的独立验证任务提供证据。

Make 的正式构建、测试与 CI 由统一启动器持有 worktree/target 独占租约；显式 target 和关闭池只改变目录选择，不关闭租约。正式 CI/T2 脚本拒绝无租约执行，ci-plan 仅预览。配置、直接 Cargo 边界及故障恢复见[本地开发](../guides/local-development.md#构建槽位与缓存)。缓存与工具链记录是诊断信息，不是通过证明。

artifacts/local-ci 中 selection/result 记录选中 gate、命令及 passed/failed/skipped；推荐 T2 与实际执行分开记录，快速检查通过不代表集成验证通过。独立 T2 结果位于 artifacts/local-t2，空选择明确为 skipped/no-modules-selected；缺依赖、零测试和 ignored 伪绿必须失败。skipped 不表示通过，affected 不称为全量。计划不覆盖正式结果，正式执行清理本入口自有旧记录。源码版本、lock 与工具链可作普通运行记录，不作“干净提交”准入。

真实候选用正式 OCI 构建及随附 Compose 输入在空库验证完整安装、启动、独立管理员和租户开通，不依赖 matching checkout、systemd 或开发 fixture。分别记录宿主 OS/架构及容器平台，仿真不代替相应原生宿主证据。候选 smoke/浏览器不替代真机；发布声明绑定实际 OS/架构、注册方式、权限、依赖、故障范围及结果。未测组合如实保留，性能、RPO/RTO 不继承历史数字。

开发/T2 环境按 worktree 隔离，独立于共享 target 槽位。`JOBS` 限制独立 case 的完整生命周期，默认 2；模块内也允许并发。普通兼容业务按对象/主体或合法专用租户隔离观察范围，共用可写库；DDL、库内权限和损坏材料使用一次性库，安装始终使用空库；共享角色和停库故障使用独立 PG 实例。故障实例恢复检查成功后可复用，失败或不确定则隔离，仅为后续 case 建立替代环境，不重跑掩盖原失败。数据库数量不由 case、模块或 worker 数决定。稳定身份、内容与签名按兼容环境准备；公共 worker 属于运行环境，精确消费者故障属专用观察域。复用需验证同库重复、换序与实际并发重叠，同对象竞争用同步点。平台工具、Identity、SCEP、Keycloak 和 HTTPS/Git 按实际需要准备。详见[测试模块](../guides/test-modules.md)。

日常 affected 与定期完整 T2 分工独立：局部 SQL/迁移登记选择安装/catalog 及实际消费者，公共准备不展开为全业务回归；纯归属说明变化由工具验证，执行策略变化选择相应模块。定期完整 T2 沿用已有安排，不叠加到每次局部修改。

扩展字段改动验证实际往返保存、完整请求幂等、签名绑定、可信投影隔离和预算；不以全部业务 key
