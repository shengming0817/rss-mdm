# 文档维护

产品需求归 docs/product，设计与架构决策归 docs/architecture，操作指南归 docs/guides，生产运行流程归 docs/deployment，历史与外部材料归 docs/reference，正式审查归 docs/reviews，稳定规则归 docs/rules。

新增文档更新所属目录 README。固定入口和长期维护文件使用稳定名称；新增过程文档使用 `yyyyMMddHHmm-编号-实际功能或问题.md`。

入库前清理对话过程、上传说明、无效附件引用、过时命名与重复结论。有效的历史证据移入 reference，并明确快照来源与证据限制；不能将旧实现状态冒充为当前产品状态。

引用须指向可定位文件或公开来源；本地忽略材料说明恢复方法。缺失来源标为缺失，不伪造引用或宣称完成复核。需求编号与验收编号保持稳定，实质需求变更须说明原因与影响。

草案、已决定目标、历史判断、已实现和已验证状态分别标识。涉及行为变更同步更新对应 owner 文档，临时清理报告和工具日志仅保留本地。
